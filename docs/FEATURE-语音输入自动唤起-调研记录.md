# FEATURE：输入框自动唤起输入法语音输入 — 调研记录

> 日期：2026-08-28
> 状态：**待决策**（功能是否做、走哪条方案，用户尚未拍板）
> 项目：FocusCapture（WPF / .NET 8，win-x64）
> 参与：彭杰 + 虾哥

## 一、需求原述（用户原话还原）

- 目标：打开输入框后自动调用**系统输入法**（微信/豆包/千问输入法）的语音输入，省掉手动按快捷键。
- 手段：程序代码模拟键盘按键（SendInput 类），自动按下输入法的语音快捷键。
- 链路：快捷键/悬浮球调出输入框 → 输入框加载 → 获得焦点 → 输入法挂载到该焦点 → 模拟按下语音快捷键 → 语音条弹出即可说话。
- 设置项：① 开关：是否默认自动调用语音；② 快捷键配置：用户自填，必须与输入法内设置的语音快捷键一致。

## 三、方案对比

| 方案 | 思路 | 优点 | 缺点 |
|---|---|---|---|
| A 模拟按键（用户原方案） | 唤起输入法云端语音 | 识别质量好、无额外模型 | 依赖输入法机制、需实测、绑定具体输入法 |

## 四、前置问题调研结论（2026-08-28 查证）

### 4.1 三家输入法语音快捷键（事实）

| 输入法 | 默认快捷键 | 说话模式 | 可自定义 |
|---|---|---|---|
| 微信输入法 | 长按 Ctrl+Win 说话，松手结束；Ctrl+Win+Shift 按一次开始/再按结束 | 按住 / 持续 | 是 |
| 豆包输入法 | 长按右 Alt；右Alt+空格、左Ctrl+Win 免按模式（按一次开始，按任意键结束） | 按住 / 免按 | 是 |
| 千问输入法 | 长按右 Alt（macOS 右 Command）；双击右 Alt 进 AI 指令模式 | 按住 / 双击 | 是 |

共同点：三家都是**全局热键**，都可自定义 —— 与"设置里配快捷键"的设计天然匹配。

### 4.2 机制判断

- 事实（AHK 官方论坛）：模拟按键 SendInput **能触发 RegisterHotKey 注册的热键**。
- 事实（社区实证）：GitHub 开源项目 `doubao-voice-helper`（AHK v2，2026-01 更新）核心流程 = 程序模拟发送语音快捷键唤起语音条 → 说话 → 剪贴板取回文字插入光标，与本案同构，已有实战。
- 判断（未验证）：三家输入法各自用哪种注册机制、是否过滤注入按键，**必须本机实测**。

### 4.3 从 doubao-voice-helper 抄到的两个设计答案

1. **感知语音条是否弹出的解法 = 监听剪贴板**：语音识别结果写入剪贴板，检测到变化即识别成功，自动粘贴回输入框。FocusCapture 已有 ClipboardHookService，现成可抄。
2. **优先用"切换型"快捷键**（微信 Ctrl+Win+Shift / 豆包免按模式）：模拟一次按键即进入语音状态，避免"按下-保持-松开"状态管理。

### 4.4 已知坑

- **微信输入法 vs 电脑版微信键位冲突**：两者语音快捷键同为 Ctrl+Win，用户同时开微信时无法判断唤起的是哪个。设置页需提示避开。
- 静默失败：应用无法直接感知语音条状态，需剪贴板信号 + 降级提示。
- 绑定输入法：换输入法可能失效，功能被第三方牵着走。

## 五、PoC 最小验证方案（30 分钟级别，先不做设置 UI）

1. `InputWindow.Show()` 后延迟约 500ms（等焦点 + IME 挂载完成）。
2. SendInput 模拟发送一次写死的快捷键（切换型优先）。
3. 验收（现象级，无需懂代码）：语音条弹出、说话出字 = 通过；没弹 = 方案转 B/C。
