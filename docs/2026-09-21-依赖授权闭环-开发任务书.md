## 1. 背景（一句话）

飞书授权在第二台电脑上永远出不了二维码。根因：应用只做了 `auth login`（用户授权），**没做 `config init`（应用凭据配置）**；且 `config.json` 只是 keychain 引用，拷文件不搬密钥。详见设计稿 §1。

## 2. 目标

- **L1**：应用内补齐"应用凭据配置"闭环 —— **乙为默认**（`config init --new`，浏览器里创建应用）、**甲为兜底入口**（粘贴 appId+secret）
- **L2**：依赖机制抽象（授权协议可插拔 + 前置配置位 + 依赖表改注册式）
- **L3**：Agent 通道 —— 预置一个"桥接 Skill"，让 AI 用上 lark-cli **官方内嵌的 28 个 skill**（不要自己写飞书业务知识）
- **L4**：运行时按需下载（打包默认不带 `runtime`，查找顺序"自带优先 → AppData 兜底"，**用户点击才下载、带进度**，lark-cli 与 Python 一起走）

## 4. 关键技术要点（踩了就白干）

- **R1（高危）**：`config init --new` 是**阻塞**命令（输出 URL → 等用户浏览器完成 → 才退出），而现有 `SkillProcess.RunAsync` 是"进程退出后才读输出"、超时还丢弃已读内容 → **照现状直写永远拿不到 URL**。必须先让它支持流式读取 + 超时保留已读内容。
- **R2（高危）**：`SkillScriptRunner.BundledPathPrefix()` 只把"自带目录"前置到 PATH。按需下载后 lark-cli 落在 AppData → 脚本里 `shutil.which("lark-cli")` 找不到 → 桥接脚本直接失效。改成"所有候选目录都前置"。R3（`SkillRuntime` 的 Python 路径是固定拼接）同源，一起改。
- **乙的 UI 文案**：用户旅程是两步（**浏览器创建应用 + 扫码**），**不许写"扫码即可"**。照设计稿 §4.1 的旅程如实写。
- **凭据纪律（硬线）**：secret 只经 stdin 交给 lark-cli，**不进代码、不进仓库、不进分发包、不进日志，应用不留任何副本**。**绝不要让用户把 secret 发给你**。
- **别凭想象写解析**：CLI 的输出字段、是走 stdout 还是 stderr，都先跑一次看真实结果再写。
- 官方能力入口（已实测）：`lark-cli skills list` / `lark-cli skills read <name>` / `lark-cli <domain> --help` / `lark-cli schema <svc.res.method>`；命令自带风险分级 `read|write|high-risk-write`。

## 6. 环境坑（本项目实测过）

- **PowerShell 侧 git 出不了网**（退 128 且零输出）→ push / ls-remote 一律走 bash
- 写文件工具会"报成功但没写入" → 落笔后必须 Grep 复核；**同一文件一轮里多个 Edit 必须串行**
- bash 侧 coreutils 全灭（`ls`/`find`/`cat`/`grep` 全 127）→ 探测走 PowerShell，结果落 `%TEMP%` 文件再读
- **`Start-Job` / `Process.Start` 被沙箱拦** → 需要起进程的探针写成项目内独立 csproj（参考 `tools/clipdiag/`）
- 编译前补 `APPDATA` / `PROGRAMFILES` / `ProgramW6432` / `ProgramData`（或直接用 `dev.ps1 build`，它自带补丁）
- `.bat` 不能含中文；`git commit` 传中文要用 `-F <utf8 文件>`
- `runtime\` 在 `.gitignore`；`builtin-skills\` **必须进仓库**（与 runtime 相反），改 `.gitignore` 时注意

## 8. 第一个动作（现在就做）

写一个隔离探针（建议 `tools/depdiag/`，独立 csproj，参考 `tools/clipdiag/` 的写法），在**隔离的用户目录**里跑：

```
lark-cli config init --new
```

要抓的是：**它输出的真实格式**（字段名、URL 在哪一段、JSON 还是纯文本、stdout 还是 stderr、是流式先吐 URL 还是最后一起吐）。

硬要求：
- **绝不能碰用户真实的 `~/.lark-cli`** —— 用临时 `USERPROFILE` 指向 `%TEMP%` 下的隔离目录
- 同时清掉 `HERMES_HOME` / `OPENCLAW_HOME` / `LARK_CHANNEL` / `PYTHONPATH`（否则 lark-cli 会走 hermes 分支报 not bound）
- 探针要有超时保护，**超时后保留已读输出**（这本身就是 R1 的验证）
- 拿到真值后先向用户汇报格式，再往下写代码
