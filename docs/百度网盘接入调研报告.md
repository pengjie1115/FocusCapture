# 百度网盘接入调研报告

> 调研日期：2026-09-15
> 目标应用：FocusCapture（C# WPF / .NET 8，本地优先）
> 调研方式：官方文档原文 + 本机真实网络端点实测（未使用任何真实账号凭据）
> 证据分级：**【一手】**官方文档/开源源码/本机实测 ·**【二手】**第三方实测/教程 ·**【判断】**我的推断 ·**【未验证】**无法证伪

---

## 一、一句话结论

**能接。走官方开放平台 OAuth 直连，不借道官方 CLI。**

个人开发者路径通畅：实名认证可即时完成、应用**免审核直接上线**、可建 1 个应用、限 10 个用户使用。

但有三个必须接受的边界（详细见第五节）：
1. **能力被锁在沙箱目录**：应用只能读写自己名下的 `我的应用数据/{应用名}/`，碰不到用户网盘其他位置
2. **下载速度不由你决定**：与账号会员等级挂钩，官方另售"极速流量权益"
3. **10 用户上限**：自用够，产品化需走"公开发布"审核

| 查了什么 | 结果 | 等级 |
|---|---|---|
| 授权介绍页（官方） | 三种模式：授权码 / 简化 / **设备码** | 【一手】 |
| 授权码模式页（官方） | 端点 `https://openapi.baidu.com/oauth/2.0/authorize`；`scope` 固定为 `basic,netdisk` | 【一手】 |
| 授权码模式页（官方） | **官方示例中 `redirect_uri=oob`** —— 无 server 的桌面应用可直接用 | 【一手】 |
| 回调地址页（官方，更新于 2026-08-07） | 原文「**您也可传 redirect_uri=oob**。回调后会返回平台默认回调地址 `http://openapi.baidu.com/oauth/2.0/login_success`」；支持配多个、修改后 1 小时生效 | 【一手】 |

| 设备码模式页（官方） | 授权两步：**扫二维码** 或 **打开 verification_url 输入 user_code**；已登录百度账号的设备扫码可免登录直接授权 | 【一手】 |
| Token 时效（官方，三处一致） | Access Token **30 天**，可刷新；refresh_token **有效期 10 年**，但**只能使用一次**，用完必须换新的 | 【一手】 |
| 简化模式（官方） | Access Token 30 天，**不支持刷新**，到期用户须重新授权 → 不适合本应用 | 【一手】 |

> ⚠️ **纠正一条旧记录**：项目记忆里写的「Refresh Token 10 年」需精确化 —— refresh_token 确实 10 年有效，但**是一次性的**，每次刷新都会作废旧的。实现时必须持久化最新 refresh_token，否则一次刷新失败就要求用户重新授权。

### 2.3 端点真实性实测（本次关键动作）

用**无效凭据**直接打真实端点，验证文档不是纸面功夫。**这一步专门用来排查昨天夸克那种「文档/工具存在，实际用不了」的情况。**

| 端点 | 实测返回 | 结论 | 等级 |
|---|---|---|---|
| `openapi.baidu.com/oauth/2.0/device/code` | `{"error":"invalid_client","error_description":"unknown client id"}` | **端点在运行、参数结构正确**；换成真 AppKey 即可工作 | 【一手·实测】 |
| `openapi.baidu.com/oauth/2.0/authorize` | `http_code=200` | 授权页可达 | 【一手·实测】 |
| `pan.baidu.com/rest/2.0/xpan/file?method=list` | `{"errno":-6,"request_id":...}` | 数据接口在运行，`-6` = 未授权（符合预期） | 【一手·实测】 |
| `openapi.baidu.com/oauth/2.0/login_success` | `http_code=200` | oob 落地页存在 | 【一手·实测】 |

**与夸克的关键差异**：夸克的死因是「官方 CLI 校验宿主环境白名单，第三方应用无门」。百度这条路是**纯 HTTP API + 你自己的 AppKey**，链路上不存在"宿主识别"这一环 —— 谁调用都一样。这不是推测，是端点语义决定的。

## 三、三条路线对比

| 路线 | 可行性 | 代价 | 推荐度 |
|---|---|---|---|
| **A. 设备码模式 + 官方 API 直连** | 高 | 需自备 AppKey/SecretKey；用户授权时打开浏览器输 user_code 或扫码；桌面端内置 secret（无 PKCE，无法避免） | ⭐ **推荐** |
| **B. 授权码模式 + `redirect_uri=oob`** | 高 | 用户授权后落到百度默认成功页，需**手动复制** code 回填 → 体验差一截 | 备选 |
| **C. 借道官方 bdpan Skill / CLI** | 中 | 多一层 Node 运行时依赖 + 官方安装脚本会改系统环境；**且同样受 `/apps` 沙箱限制**，能力不比直连多；若它像夸克那样校验宿主，直接归零 | 不推荐 |
| **D. 零代码降级：同步盘手动搬运** | 高 | 用户手动把文件拖进网盘客户端；无自动化 | 兜底 |

**为什么不选 C**：昨天的教训是「官方给了命令行工具 ≠ 官方开放了通道」。百度这条路好在**有正规开发者凭据体系**，直连 API 能力等价且少一层依赖，没有任何理由去赌 CLI 的宿主白名单。

## 四、接进来是什么样（能力画像）

**能做的：**
- 把 AI 生成的内容（笔记、生成的文档、图片）上传到 `我的应用数据/{应用名}/`
- 列出该目录、搜索该目录、下载回本机
- 创建子目录、重命名、移动、删除（限该目录内）
- 获取文件元信息、下载直链（8 小时有效）

**不能做的：**
- 读写用户网盘其他任何位置（个人相册、工作文档、电影……）——**默认被平台锁死**
- 把用户网盘里的旧文件"移进来"（`move` 受限）
- 让下载快起来（除非用户是会员，或你购买极速流量权益）

**用户侧的操作路径**：在百度网盘 App / 客户端里找到「**我的应用数据**」文件夹 → 里面有本应用的专属目录 → 想交给 AI 处理的文件拖进去。

> 这个设计**对 FocusCapture 反而是对的**：本项目定位「本地优先、数据全本地」，只碰自己的沙箱目录、绝不扫描用户私人网盘，正好符合项目一贯的数据安全立场。

## 五、丑话（必须提前知道的）

1. **`/apps` 沙箱是硬限制，不是配置项**。2026-06-03 后创建的应用一律如此，没有申请豁免的说明。任何"能不能让 AI 读我网盘里已有的资料"的期待，都会在这里撞墙。
2. **下载速度是别人的开关**。官方 FAQ 明说速度与会员身份挂钩，`from_apaas` 极速流量是**付费商务权益**。这意味着"AI 生成 → 存网盘 → 以后取回"这条链路里，**取回这一段的速度不由你控制**。若用户非会员，取回大文件可能慢到不可用。
3. **10 用户上限**。个人认证应用只能服务 10 个用户，且规范明确禁止「多人共享开发者账号」——想靠这个做产品必须先走"公开发布"审核（面向公众分发，需提交上线审核）。
4. **桌面端必须内置 SecretKey**。百度 OAuth 没有 PKCE，无 server 的桌面应用只能把 client_secret 打包进程序。自用无妨，公开分发等于公开"应用身份"（别人可冒用你的应用名做授权）。这是全行业桌面 OAuth 的通病，不是百度特有缺陷。
5. **规范红线**：官方使用规范明确禁止「利用个人网盘账号进行**企业建站、图床、搭建网盘迁移工具**」及越权访问用户数据。做"AI 助手存文件"没问题，做"网盘迁移/图床"会被封。
6. **⚠️ 真正决定工期的可能是我们自己这侧**：Agent 层目前拿不到本地文件路径（`LocalTools.cs` 全部工具只作用于笔记库）。**不先补「选择文件」入口或受目录限制的文件工具，接什么网盘都白搭**。这一项比"百度能不能接"更卡人。

## 六、实施路线（待你拍板后再动手）

### 第一步：门户侧动作（只有你能做，约 10 分钟）

1. 访问 `https://pan.baidu.com/union/`，右上角「申请接入」，用百度账号登录
2. 完成**个人实名认证**（身份证 + 手机 + 邮箱，官方称即时通过）
3. 进控制台 `https://pan.baidu.com/union/console/applist` 点「创建应用」
   - 应用用途：选 **【个人使用】**（免审核直接上线）
   - 应用类型：选 **【软件】**（选定不可改）
   - 应用名称：0–12 字，只允许汉字/字母/数字/空格/`-`/`_`
   - 应用描述：**至少 30 字**，同样限字符集
4. 记下 **AppKey / SecretKey / AppID**
5. 回调地址：若走设备码模式可不配；走 oob 模式时 `redirect_uri` 直接传 `oob`

### 第二步：授权链路（推荐设备码模式）

```
1) GET https://openapi.baidu.com/oauth/2.0/device/code
       ?response_type=device_code&client_id={AppKey}&scope=basic,netdisk
   → 拿到 device_code / user_code / verification_url / qrcode_url

2) 界面展示二维码（qrcode_url）或提示用户访问 verification_url 输入 user_code

3) 每 ≥5 秒轮询：
   GET https://openapi.baidu.com/oauth/2.0/token
       ?grant_type=device_token&code={device_code}
       &client_id={AppKey}&client_secret={SecretKey}
   → 拿 access_token + refresh_token

4) 用 access_token 调业务接口（须带 User-Agent: pan.baidu.com）
```

**必须实现的两件事**：
- Access Token 30 天到期前用 refresh_token 刷新，**每次刷新后立刻持久化新的 refresh_token**（旧的会当场作废）
- 授权码/SecretKey 走项目既有的 **Dpapi 加密存储**，绝不落明文

### 第三步：代码侧（描述，不实施）

按项目既有架构，这是**「文件存/取」语义 → 普通工具类**，不是目的地适配器：

- 新增一个 `AgentTool` 子类（或一组），封装：上传 / 列出 / 下载 / 建目录 / 删除
- 在注册表加一行装配
- 复用 `Dpapi` 存凭据、复用现有 HTTP 客户端与重试策略
- **不碰** `IOutboundDestination`（那是"外发/发布"单向语义，套上去属过度设计）

预估新增：1 个服务类（百度网盘客户端封装）+ 1 个工具类 + 设置面板加 2 个输入项（AppKey/SecretKey）+ 一个授权按钮。
