# TASK.md — FocusCapture v2.0 AI 能力增强（总规划）

> **人类阅读** | 2026-08-09 | 每轮方向确认时读这份，不读 QUEST 细节

## 项目一句话

给 FocusCapture（WPF .NET 8 本地专注力工具）的「灵感速览」注入 AI 能力：翻译 / 搜索 / 问答三板块 + 连续对话 + 笔记编辑 + 面板体验升级。

## 分 4 轮（每轮一个可验收增量）

| 轮次 | QUEST | 内容 | 验收要点 | 预估 |
|---|---|---|---|---|
| 1 | QUEST-1 | 基础设施：LLM Provider 抽象层、模型配置页（BYOK）、查词接口抽象、笔记编辑（双击/保存/沉浸锁定） | 配置 Key 后能发起对话；笔记可编辑、锁定生效 | 3-5 天 |
| 2 | QUEST-2 | AI 核心：三板块对话框、连续对话、流式输出、全部入口、回填机制、提示词动态适配 | 三板块可对话；单词/段落表现正确；回填追加生效 | 4-6 天 |
| 3 | QUEST-3 | 面板完善：刷新按钮、日历热力图、多选删除、标题栏改造、MD 同步（方案 B）、输入面板（语音/快捷键修复） | 面板操作流畅；MD 只增不减；快捷键唤起可直接输入 | 4-6 天 |
| 4 | QUEST-4 | 个性化：AI 助手名称自定义、托盘图标自定义、主题配色统一、正式 .ico | 设置项生效，三处入口同步改名（面板/悬浮球右键/托盘），图标可换 | 2-3 天 |

执行方式：**每轮完成后验收通过，再进下一轮**。不要一次把所有 QUEST 丢给 Codex。

## 全局红线（跨所有轮次）

1. **业务代码不得直接调 LLM API**，必须走 `IChatProvider` / `ITextExplainService` 接口（Phase 1 立规矩）
2. 配置一律进 `AppSettings`（%AppData%\FocusCapture\settings.json），**不硬编码 Key/URL/模型名**
3. **不破坏 v0.1 现有功能**：剪贴板捕获、悬浮球、沉浸式语音识别、导出——改动后必须回归
4. **不动** `.github/` CI、`asr_venv/`、Release 单文件发布配置（`PublishTrimmed=false` 不能改回裁剪）
5. **沉浸式锁定统一覆盖编辑 + AI 回填**（Phase 1 立规矩，后续复用）
6. 存储层 MD 文件**只增不减**（编辑/回填追加行，不覆盖原行）——Phase 1 临时覆盖、Phase 3 改为追加
7. 每轮结束必须 `dotnet build` 通过 + Release 构建验证

## 范围外（不做）

- 账号体系 / 云同步 / 后端存储
- 本地离线词库（仅留 `ITextExplainService` 接口扩展位）
- 联网搜索（架构留 tool calling 位）
- 全库语义搜索 / 向量检索
- Anthropic 协议适配
