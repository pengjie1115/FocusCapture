# 网盘语义检索 —— 可行性评估

> 日期：2026-09-27
> 分支：`experiment/netdisk-semantic-eval`（**评估阶段，主项目代码零改动**）
> 起因：用户提问「百度网盘好像有开放语义检索的接口」，要求先核实、再评估
> 结论一句话：**接口真实存在且很新，但对我们有没有用，取决于一个未公开、且只能实测的未知数（沙箱目录是否被预处理）**

---

## 一、核实结论：确实有，而且官方在做两条路

### 1.1 开放平台接口 `/xpan/unisearch`（官方文档更新时间 **2026-09-08**）

| 项 | 内容 |
|---|---|
| 接口 | `POST https://pan.baidu.com/xpan/unisearch`，`Content-Type: application/json` |
| 能力 | 关键词搜索 + **自然语言描述**搜索。官方示例：简单 `AIGC 前沿`；复杂 `帮我搜索科技专栏文件夹下的 AIGC 相关文档` |
| 返回 | `data[].list[]`，字段含 `path`（**完整路径**）、`filename`、`fsid`、`category`、`size`、`server_mtime`、`ocr`、`content`（召回的文本段落）、`pid` |

请求参数（原文摘要）：

| 参数 | 必填 | 说明 |
|---|---|---|
| `access_token` | 是 | 鉴权令牌 |
| `scene` | 是 | 搜索场景，**固定传 `mcpserver`** |
| `query` | 是 | 搜索内容 |
| `dir` | 否 | `[]string`，指定搜索路径，**默认根目录 `["/"]`** |
| `category` | 否 | `[]int`：1 视频 / 2 音频 / 3 图片 / 4 文档 / 5 应用 / 6 其他 / 7 种子 |
| `num` | 否 | 返回最大数量，默认 500 |
| `stream` | 否 | 是否流式响应，默认 0 |
| `search_type` | 否 | 0 简单 / 1 语义 / **2 自动（>5 字走语义）**，默认 0 |
| `sources` | 否 | 召回来源。**关键词类**：4 文件名 / 5 图片 OCR / 11 文档文本 / 13 卡证 / 14 图片语义；**向量类**：7 文档 / 8 视频 / 9 音频 |
| `data` | 是 | 示例传空对象 `{}` |

`sources` 默认值随 `search_type` 变：简单搜索 `[4,5,11,13,14]`；语义搜索 `[4,5,11,13,14,7,8,9]`。

**支持能力（原文要点）**：文件名搜索支持关键词/文件夹等单维度，也支持「时间+关键词+后缀」多维度；文件内容搜索**需先完成对应的文件特征预处理**：

| 文件类型 | 支持能力 |
|---|---|
| 图片 | 文本搜图、以图搜图；分类 / 拍摄时间 / 地点(POI) / 人脸 / OCR / 图片向量 |
| 文档 | 内容关键词搜索或问答、**语义搜索或问答**；支持 Word / PPT / PDF（含影印版）/ Excel / TXT |
| 视频 | ASR 关键词搜索或问答、语义搜索或问答 |
| 音频 | ASR 关键词搜索或问答、语义搜索或问答 |

### 1.2 官方 MCP Server（github.com/baidu-netdisk/mcp）

百度把网盘核心 API 做成了 MCP Server，**语义检索在里面是一个现成工具**：

| Tool | 说明 |
|---|---|
| `file_semantics_search` | 自然语言描述搜索文件；入参 `dir` / `query`；出参含 `path` / `content` / `abstract` / `thumbnail` |
| `file_keyword_search` | 文件名关键词搜索；入参 `dir` / `key` / `page` / `num` |
| `file_list` / `file_doc_list` / `file_image_list` / `file_video_list` | 列目录（**`dir` 默认 `/`，即整个网盘**） |
| `file_meta` / `file_copy` / `file_move` / `file_rename` / `make_dir` / `file_upload_by_url` / `file_sharelink_set` / `user_info` / `get_quota` | 其余文件与用户能力 |

接入方式（原文）：
- **SSE**：`https://mcp-pan.baidu.com/sse?access_token=<ACCESS_TOKEN>`（**不含上传工具**）
- **stdio**：Python + `uv`，env `BAIDU_NETDISK_ACCESS_TOKEN`（含上传）
- 授权是**独立入口**：README 里个人用户标注 **「限时体验」**，通过网页授权页复制 token

> ⚠️ 这跟我们应用现在的授权**不是同一套**。我们走的是开放平台授权码模式（`scope=basic,netdisk` + `device_id`），MCP 的 token 走它自己的授权页。

### 1.3 配额：官方口径互相矛盾，且 unisearch 只字未提

| 来源 | 原文口径 |
|---|---|
| 《权限与配额》页（2026-07-03） | 未通过/未提交上线审核的应用：**10 次 / 每小时** |
| FAQ《调用搜索文件接口频率规则限制在是什么》（2022-03-09） | **搜索接口限定每人每日的请求次数是 2000 次** |
| FAQ（同页） | `listall` 接口的请求频率建议不超过 **每分钟 8–10 次** |
| **`unisearch` 文档** | **完全没有配额说明** |

三者相差几个数量级（10/小时 vs 2000/天 vs 8-10/分钟），说明**配额是按接口分别规定的**，而 `unisearch` 的口径**未公开** —— 只能实测。

### 1.4 使用规范红线（官方原文）

被禁止的行为包括但不限于：
1. 侵犯用户数据隐私 —— 未经用户授权、用户不明确知晓的场景中违规下载使用、传播用户网盘数据；
2. 违规作弊、侵犯百度网盘商业利益，比如多人共享开发者账号、多人共享个人网盘账号及会员权益；
3. **利用个人网盘账号进行企业建站、图床、搭建网盘迁移工具等产品行为**。

对本项目（个人自用、单用户、数据全本地、不上云）第 3 条风险低，但若将来对外分发，必须保证「每个用户各自授权自己的网盘」。

## 二、先把三件事分清（最容易混）

| # | 能力 | 现状 | 本次核实的接口能解决吗 |
|---|---|---|---|
| 1 | **本地元数据检索**（`find_cloud_files`） | ✅ 已有：离线、按**文件名/标签子串**匹配 | ❌ 无关 |
| 2 | **云端网盘语义检索** | ❌ 无 | ✅ **就是它**（`unisearch` / `file_semantics_search`） |
| 3 | **本地文件内容语义检索** | ❌ 无（项目零 embedding 实现） | ❌ **完全帮不上** —— 它只搜云端 |

**关键一句**：`unisearch` 搜的是**云端网盘里百度已预处理过的文件**。本机文件区里那些「还没上传 / 上传了但百度没预处理」的文件，它**搜不到**。不要把「网盘语义检索」误当成「本地语义检索」的替代品。

## 三、对我们有没有用？—— 取决于一个未公开的未知数

### 3.1 最大的未知数：沙箱目录会被预处理吗？

我们所有的文件都在 `/apps/FocusCapture/` 下（`files/` + `attachments/YYYY-MM/`）。百度侧的内容能力（文档语义 / OCR / ASR / 向量）**依赖「文件特征预处理」**，而官方文档只说「需要先完成预处理」，**没说哪些文件会被预处理、`/apps/` 应用数据目录算不算**。

两种可能，结论完全相反：

| 情形 | 后果 |
|---|---|
| ✅ 沙箱文件被预处理 | 语义召回（`sources` 7/8/9）对我们生效 → **价值大**：Agent 能按内容/语义找到网盘文件 |
| ❌ 沙箱文件不预处理 | 只剩文件名关键词（`source` 4）→ **退化成「文件名搜索」**，和现在 `find_cloud_files` 的差别只是「云端实时 vs 本地记录」，性价比低 |

**这一条不实测，整套评估就是空中楼阁。**

### 3.2 能解决什么

- 让「网盘里有没有关于 XX 的文件」这类问句，从**按文件名猜**升级到**按内容/语义找**。
- `unisearch` 返回的是**云端实时真相**，比 `listall` 逐条核对更直接 —— 顺带能缓解「本地元数据只增不减」的失真（但只覆盖"能搜到的"那部分，不能替代核对）。
- 返回字段带 `path`，**与本地 `NetPath` 同口径**（上一轮 `listall` 已实测验证过路径口径一致）→ 比对地基现成。

### 3.3 不能解决什么

1. **本地文件语义检索**（另一条独立路线，要自己建 embedding + 向量存储，项目现在零基础）。
2. **隐私边界问题**：`dir` 默认是 `"/"`（整个网盘）。若照默认走，等于**能读到用户网盘里所有文件的名字与内容片段** —— 这与本项目「只访问自己的沙箱目录」这条既有边界**正面冲突**。
3. **预处理延迟不可控**：新上传的文件何时有向量/摘要，我们无法干预。

## 四、三条接入路线

| 路线 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 自建 HTTP** | `BaiduNetdiskClient` 加 `UniSearchAsync`，POST `/xpan/unisearch` | 完全可控；**可强制 `dir` 限定沙箱**；与现有架构一致（同域、复用退避与令牌）；无新依赖 | `scene=mcpserver` 能否用我们 token 调 → 未验证；配额未知 |
| **B. 接官方 MCP Server** | 应用内置 MCP 客户端 → `mcp-pan.baidu.com/sse` | 官方维护、能力最全 | **独立授权体系**（要另拿 token）；引入 MCP 客户端依赖；`file_list` 默认全盘 → **越界**；SSE 长连；个人用户「限时体验」有政策风险 |
| **C. 只在 WorkBuddy 侧接** | 用户自己在 WorkBuddy 配 MCP | 零代码改动、立刻可用 | 与 FocusCapture 应用无关，**给不了应用内 Agent 用** |

**倾向 A**。理由：B 的权限范围是全盘、授权体系独立、还带「限时体验」，对一个「本地优先、数据全本地」的应用是反向的；C 不解决应用内 Agent 的问题。

## 五、必须实测的清单（只读、不动数据）

| # | 未知数 | 为什么决定性 | 测法 |
|---|---|---|---|
| **U1** | 现有应用 token + `scene=mcpserver` 能否调通 | 不通则 A 路线直接堵死 | POST 一次，看 `error_no` |
| **U2** | `/apps/FocusCapture/` 下的文件**是否已被预处理** | 不预处理 → 语义能力为 0，只剩文件名搜 | 用已知文件内容的语义 query 搜沙箱路径，看是否召回、`content` 是否有值 |
| **U3** | `unisearch` 的配额/频控（`31034`/`20012`？日限？） | 决定能否给 Agent 用，还是只能手动 | 看返回错误码；**不做压测** |
| U4 | `dir` 传沙箱路径是否被接受（会不会越权报错） | 决定能否守住隐私边界 | 显式传 `dir:["/apps/FocusCapture"]` |

**全部为只读操作**：搜索不修改任何文件、不写本地数据、不刷新令牌；探针输出必须脱敏（文件名不进日志）。

## 六、风险清单

1. **隐私边界**：必须**显式**传 `dir=["/apps/FocusCapture"]`，**绝不使用默认 `"/"`**。UI/授权文案要交代清楚「能搜到什么范围」。
2. **配额未知**：若与上传共享「10 次/小时」，则**绝不能**做成 Agent 可自由调用的工具 —— 这是上一轮 `listall` 已经踩过的教训（Agent 被问句反复触发 → 撞配额 + 连累上传）。
3. **官方文档自相矛盾**（文档自己承认）：`category` 类型标注 string 而示例返回数值；`data` 标注必填而示例传空 → **一律实测为准**。
4. **内容预处理不可控**：百度侧行为，我们无法干预或预测。
5. **MCP 路线另有政策风险**：个人用户「限时体验」，且授权体系独立。

---

## 七、建议（待拍板）

```
① 只读实测（不改代码、不动数据）
   → 定性 U1 / U2 / U3 / U4
        │
        ├── U2 成立（沙箱文件有预处理）
        │     → A 路线：UniSearchAsync（只读）
        │       → 先用「设置页手动触发」，观察配额
        │       → 配额够再考虑 Agent 工具（严格限流 + 描述写明联网与额度）
        │
        └── U2 不成立（沙箱文件无预处理）
              → 放弃「网盘语义检索」
              → 转做「本地文件内容检索」独立线（当时是另一套设计）
```

**决策点（需用户拍板）**：
1. 是否授权我做**只读实测**（会联网调用你账号的搜索接口，只读、不改任何数据、不写任何文件）？
2. 若可行，第一版是**只进设置页手动触发**，还是直接做 Agent 工具？
3. 「本地文件内容检索」要不要同期排期（它与网盘语义检索是两条独立的线）？
