## 二、任务 4-2 同步兼容（代码层已确认，现象级留手动）

**代码层确认（静态，无需改代码）**：

## 五、已知风险点（供实测确认，按文档"记录不阻塞"处理）

- **待办状态原地改行 → 行哈希变化**：`UpdateTodo` 整文件重写待办行，行文本（如加 `(状态: 已办)`）变化 → `ComputeId` 哈希变化 → 同步侧视为**新行**推送。
  - 本机文件层面：旧 Open 行已被覆盖，文件内只有新 Done 行 → 本机无重复。
  - 云端层面：若 Open 行已先推到云端，PushFlow 按"云端全量保留 (TryAdd 只增不减)" → 云端可能**同时残留旧 Open 行 + 新 Done 行** → 双机拉取时可能把已撤销的 Open 待办带回。
  - **处置**：这是 4-2 指出的"状态改写触发重传"类场景，属运行期才暴露。若实测确认会引入重复待办行 → 记入 BLOCKED.md，不阻塞其余任务；若实测不重现（本机推送前已完成状态变更、云端无旧行）→ 无需处理。
