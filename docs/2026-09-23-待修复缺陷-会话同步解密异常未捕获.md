## 一、缺陷概述

`ChatSyncEngine` 三处下载云端清单文件后调用 `CryptoService.Decrypt` 解密，外层注释写明降级意图为「云端文件损坏：按空处理」，但 `catch` **只捕获 `JsonException`**。而 `CryptoService.Decrypt` 在密钥不对 / 密文损坏时抛的是 **`CryptographicException`**（GCM 认证失败）或 **`FormatException`**（Base64 非法），**均非 `JsonException`**，导致：

1. 降级意图**未实现**——异常不被捕获；
2. 异常冒泡到 `RunOnceAsync` 的 `catch(Exception)`，整轮同步判定「失败」；
3. **`SyncSessionsAsync`（会话文件对账）根本不执行**——所有会话（无论新旧）停止下载 / 推送。

一句话：注释承诺「损坏按空处理」，代码实际「损坏即整轮崩」。

## 三、触发条件

云端 `chat_groups.json` / `chat_deletions.json` / `chat_restores.json` 任一**解密失败**即引爆：

- **E2EE 盐分叉**：两端盐不一致 → DEK 不同 → 解不开对方加密的清单（最现实的触发路径，提交 696270a「盐分叉自愈」即针对此类场景，但自愈只覆盖 SyncEngine，ChatSyncEngine 防抖窗口独立触发时仍会撞上旧 DEK）；
- **密文截断 / 损坏**：网络异常、服务器问题导致 PUT 内容不完整；
- **密文格式异常**：非裸 Base64 也非带引号 JSON，`UnwrapCipherJson` 兜底后仍非法。

任一命中，整轮会话同步崩溃，状态留痕「失败: …」。

---

## 四、后果链

```
云端清单解密失败
  → CryptographicException / FormatException 抛出
  → catch(JsonException) 抓不住（降级意图「按空处理」未生效）
  → 异常冒泡到 RunOnceAsync catch(Exception)
  → SetChatStatus("失败: ...")
  → SyncSessionsAsync 不执行
  → 所有会话（新/旧）停止下载与推送 = 会话同步完全停摆
```

注意：搭车 hook 里 `_chatSyncEngine.RunOnceAsync().ContinueWith(...)` 的异常会被吞掉（不崩主程序），所以故障是**静默**的，只在设置页「会话同步上次结果」留痕「失败」。若用户没看这栏，表现为「AI 问答记录莫名不同步」。

## 六、修复方向（建议，未动代码）

> 以下仅为排查建议，**未改任何代码**。实际修复须先开 `fix/` 分支并做影响面评估（AGENTS.md 红线 4）。

**核心**：让降级意图真正生效——三处 `catch (JsonException)` 扩大为可捕获解密异常的范围。

方案 A（最小改动，贴合注释意图）：
```csharp
catch (Exception) { /* 云端清单损坏/解密失败：按空处理，本地清单覆盖回去 */ }
```

方案 B（精确捕获，保留 JsonException 语义）：
```csharp
catch (Exception ex) when (ex is JsonException or CryptographicException or FormatException)
{ /* 云端清单损坏/解密失败：按空处理 */ }
```

**需同步评估的影响面**：

1. 降级为「按空处理」后，云端清单若真损坏，本地清单会覆盖回去——需确认这不会用本机（可能过时 / 错误）的清单覆盖云端，造成数据丢失。建议降级时**只读不写**（本地清单不回写云端），等下轮自愈。
2. 三处 catch 改动**必须一致**，不可只改一处（否则只堵了一个口）。
3. 建议补一条状态留痕：云端清单解密失败时，状态应区分「云端清单解密失败（已按空降级）」而非笼统「成功」，避免静默。
4. 建议补检查点：构造一份盐分叉场景（两端 DEK 不同），验证 ChatSyncEngine 降级而非整轮崩（当前 REGRESSION.md B-10 未覆盖此路径）。

## 七、备注：与当前「无法跨端」症状的关系

本次排查最终判定：**本机（cf5ebca7）完全健康**，当前「AI 问答记录无法跨端同步」的根因**不在本缺陷**，而在另一台设备 B 侧（疑似 `ChatSyncEnabled` 被关 / 盐分叉 / 旧版本，待 B 设备 `settings.json` 输出确认）。

本缺陷是**独立的确凿代码缺陷**，与当前症状无直接因果，但属同区域隐患：一旦 B 设备存在盐分叉，本缺陷会立刻引爆，使「会话同步失败」从「隐性风险」变为「显性停摆」。建议优先修复，并把它作为排查 B 设备时的备选根因之一。
