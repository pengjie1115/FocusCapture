## 项目一句话

给 FocusCapture 输入框加「笔记/待办」类型选择（UI 两入口、代码三态），待办支持提醒时间自动识别、单条到点弹窗、每日汇总、悬浮球角标。全链路本地优先，应用开着才提醒。

## 为什么做

用户实际使用中发现输入框不只是快速记笔记，还想快速记待办且能提醒。核心诉求：记待办零成本（选一下类型）、不打扰（弹窗 10 秒收起 + 每日汇总）、不遗忘（角标 + 汇总兜底）。

## 不是什么（负空间）

- 不是完整任务管理软件：不做优先级、不做子任务、不做标签树、不做闹钟式重复提醒
- 不做系统级后台提醒：应用没开提醒不响（用户明确砍掉）
- 普通笔记 = 纯记录，不参与任何待办逻辑（类型在输入框定死）
- 不做「自动判断类型」：类型永远用户手动选，识别只做「待办 → 待办+提醒」的升级

## 执行结构：1 份 QUEST-6，4 个 Phase，每 Phase 自带验收

| Phase | 内容 | 验收要点 |
|---|---|---|
| 1 底座 | NoteEntry 三态字段 + 行格式扩展 + TimeParser 规则解析 + 输入框类型 UI（两入口 + Ctrl+T + 默认类型）+ 保存升级逻辑 + 设置项 | 输入框选待办+时间 → md 出现 (提醒:) 标记行；Ctrl+T 切换；设置默认类型生效 |
| 2 面板 | 待办徽标、点标签已办（原地改行）、已办沉底、编辑识别建议（LLM 兜底）、右键设/取消提醒、4 档筛选+来源筛选 | 面板操作全部落盘可查；重启状态保留 |
| 3 提醒 | ReminderService 定时器、单条弹窗（已完成/稍后提醒/已知悉）、同分钟合并、每日汇总弹窗（默认 18:00）、汇总窗分组（待处理/已暂缓）、悬浮球角标（红/默认色）、启动检查 | 到点弹窗、稍后循环、已知悉挂起、角标计数正确 |
| 4 兼容 | 导出 `- [ ]` 格式、同步行级兼容验证、旧数据默认笔记 | 导出含待办标记；双机同步待办状态一致；老笔记不受影响 |

执行方式：Phase 顺序推进，每个 Phase 完成后跑该 Phase 验收 + git commit 固化；全部 Phase 完成后跑总验收，验收通过合 main + 推送。

## 全局红线（v3.5）

1. 类型判定只发生在输入框，面板不自动改类型（只做建议确认）
2. 待办状态变更（未办→已办/已读、提醒时间）必须原地改行，禁止追加标记行模拟
3. 规则优先：能正则解析的时间绝不调大模型；输入框场景规则未命中不调 LLM
4. 应用没开提醒不响（已确认砍掉系统级方案）
5. 深色 UI 全项目一致，新增控件保持 #1E1E1E / #3A3A3A / #E0E0E0 配色系
6. 旧数据（无待办标记的行）永远按普通笔记解析，不允许破坏兼容

## 已知作弊姿势清单（反作弊回流）

1. **状态变更用追加行** — 已办/已读/提醒变化追加新行（违反只增不减例外）。验证：操作后 grep 原行已被改写、无重复行
2. **时间解析一次正则穷举** — 正则写个 `\d+:\d+` 就交差。验证：TimeParser 测试覆盖 今天/明天/周X/上午/下午/N小时后/日期 等 10+ 用例
3. **已办只改内存不落盘** — 面板点标签只改 ViewModel 不写文件。验证：重启应用状态保留
4. **面板编辑识别不调 LLM** — 模糊表达也靠正则硬解。验证：规则未命中的输入触发 LLM（日志/调试输出）
5. **筛选走前端 filter** — 类型筛选只过滤当前已加载列表。验证：筛选条件在 ReloadNotes 时仍生效
6. **提醒用 Thread.Sleep 循环** — 阻塞 UI 线程。验证：代码审查用 DispatcherTimer，无 Sleep

## 人类验收抽查点（暗卷，执行 Agent 不可见）

> 不懂代码也能验。做完对应 Phase 后照着抽。

- P1 抽 1：输入「明天上午9点 交报告」，选待办保存 → 打开 `文档/FocusCapture/灵感_当天.md`，看到 `【待办】交报告 (提醒: ...)` 字样，且无多余重复行
- P1 抽 2：输入框按 Ctrl+T，下方类型按钮在「笔记/待办」间切换
- P2 抽 1：面板点待办标签 → 该条变灰加删除线，且 md 文件里该行多了 `(状态: 已办)`
- P2 抽 2：筛选点「待办」只看待办；点「已办」看已办；「全部」恢复
- P3 抽 1：设一条 2 分钟后提醒的待办 → 2 分钟后弹窗，点「稍后提醒」→ 过 N 分钟（设置改短）又弹
- P3 抽 2：汇总弹窗（18:00 或手动触发）列出未办待办；点角标数字 → 汇总窗分「待处理/已暂缓」两组
- P4 抽 1：导出 md → 待办是 `- [ ] 内容`，已办是 `- [x] 内容`
- P4 抽 2：同步后另一台（或模拟双机）待办状态一致
