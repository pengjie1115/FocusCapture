# FocusCapture v3.0 产品需求文档（PRD）— 云端同步与账号体系

> **版本**: v0.3（含 Phase 0 演进路径，需求确认完毕）  
> **日期**: 2026-08-12  
> **状态**: 需求确认完毕，待开发（详见 §11 变更记录）  
> **关联**: GitHub pengjie1115/FocusCapture（MIT，v0.1.0 已开源；v2.0 AI 增强开发完成待验收合并）  
> **路线**: 两阶段演进 —— **Phase 0 坚果云 WebDAV 自用过渡（0 成本）→ Phase 1-4 自建服务器商业化**，两条路共用一套客户端同步架构，互不废弃

---

## 1. 背景与目标

FocusCapture v0.1.0 是 WPF .NET 8 本地专注力工具（悬浮球 + 剪贴板捕捉 + 灵感速览 + 本地语音识别），v2.0 注入 AI 三板块。当前所有数据仅存本机，无账号、无云端、无多端。

**v3.0 核心目标**（两阶段）：

1. **Phase 0（先做，自己用）**：零成本、零运维实现多端同步——客户端接入**坚果云 WebDAV**（免费），不买服务器、不备案、不装域名
2. **Phase 1-4（后做，商业化）**：建立**账号体系**（邮箱+密码注册登录 + JWT）+ **自建服务器云端同步**，为商业化奠基
3. **两阶段不冲突、不废弃**：客户端同步架构按**可插拔设计**（ISyncProvider 契约层），Phase 0 接 WebDAV、Phase 1-4 接自建服务器，**切换只换一个 Provider 实现，同步引擎、冲突处理、UI 全部复用**
4. **商业化留白**：数据结构与架构按多用户设计，`tier` 字段预留但本版不做付费逻辑

**与 v2.0 关系**：v2.0（AI 增强）与 v3.0（账号云端）是两条独立增强线，均基于 v0.1.0，无代码依赖，可并行开发、顺序合并。

## 2. 产品演进路径总览

### 2.1 两阶段全景

```
Phase 0（现在，自己用）               Phase 1-4（将来，商业化）
┌──────────────────────────┐      ┌──────────────────────────┐
│ FocusCapture 客户端       │      │ FocusCapture 客户端       │
│ ├── 同步引擎（写死）      │      │ ├── 同步引擎（复用）       │
│ ├── ISyncProvider 契约   │      │ ├── ISyncProvider 契约    │
│ │   ├ WebDAVProvider  ✅ │ ──►  │ │   ├ WebDAVProvider（关）│
│ │   └ ServerProvider     │      │ │   └ ServerProvider ✅  │
│ ├── E2EE 加密（做）       │      │ ├── E2EE 加密（复用）      │
│ └── 本地回收站（做）      │      │ └── 账号体系（新增）       │
├──────────────────────────┤      ├──────────────────────────┤
│ 坚果云（免费，WebDAV）    │      │ 自建服务器 + JWT + 账号    │
└──────────────────────────┘      └──────────────────────────┘
```

**演进规则**：切换渠道 = 客户端配置从"坚果云 WebDAV"改为"自建服务器" + 一次数据迁移（§5.0.8），**同步引擎、数据格式、冲突处理、E2EE、本地回收站全部零改动**。Phase 0 积累的云端数据通过迁移工具导入服务器，非废弃重建。

### 2.2 可插拔架构原则（本 PRD 的架构基石）

客户端不直接依赖任何具体存储渠道，同步能力拆成**两层**：

| 层 | 内容 | 是否可换 |
|---|---|---|
| **契约层（ISyncProvider）** | 定义同步语义：`增量推送`、`增量拉取`、`软删传播`、`全量导出`；同步引擎与 UI 只认这层 | 写死 |
| **翻译层（Provider 实现）** | 把语义翻译成渠道方言：WebDAV = `PUT 文件 / PROPFIND 列表`；自建服务器 = `POST /api/notes / GET ?since=` | 可换 |

**三件套解耦**（缺一不可，否则仍算焊死）：

1. **接口契约**：上述 ISyncProvider 抽象
2. **数据格式统一**：笔记序列化格式（§5.0.3）两端一致——WebDAV 阶段 = 云端文件内容，服务器阶段 = 数据库行，**同一份 JSON**
3. **频率策略参数化**：同步频率不写死在引擎里，由 Provider 上报自己的限流规则（§5.0.5），换渠道自动适配

### 2.3 两阶段能力对照

| 能力 | Phase 0（WebDAV 自用） | Phase 1-4（自建服务器） |
|---|---|---|
| 账号体系（注册/登录/找回密码） | ❌ 无（用坚果云账号） | ✅ 邮箱+密码+JWT |
| 多端同步 | ✅ 坚果云 WebDAV | ✅ 自建 API |
| 数据加密 | ✅ E2EE 客户端加密（云端只存密文） | ✅ 同一套 E2EE，复用 |
| 本地回收站 | ✅ | ✅ 复用 |
| 同步频率 | 克制（30 秒合并 + 30 分钟轮询） | 激进（3 秒推送 + 1 分钟轮询） |
| 成本 | 0 元 | ~125-150 元/年（服务器 99 + 域名 ~30） |
| 运维负担 | 无 | 补丁/备份/监控 |

## 4. 用户场景

1. **多端场景（Phase 0 主场景）**：主力电脑记录灵感，第二台电脑配置同一坚果云 WebDAV → 拉取全部笔记；任意一端新增/编辑/删除，另一端同步后一致（30 秒~30 分钟延迟，自用无感）
2. **备份场景（Phase 0）**：本机硬盘损坏/重装系统后，重新配置 WebDAV 一键拉回全部笔记（本地事实源声明保证：本地优先、云端为镜像）
3. **账号管理场景（Phase 1-4）**：通过悬浮球右键"主页"查看/修改昵称头像、管理云端数据、退出登录
4. **找回密码场景（Phase 1-4）**：忘记密码 → 登录窗"忘记密码" → 输入邮箱收验证码 → 验证码 + 新密码重置
5. **E2EE 密钥重置场景（Phase 0）**：忘记主密码 → 云端密文不可解（本地明文完好）→ 输入新主密码重新加密 → 全量重新上传 → 同步恢复（§5.0.7 密钥重置流程）
6. **迁移场景（Phase 0 → 1-4）**：商业化启动时，客户端内置迁移工具按"切换时刻状态机"把坚果云数据导入自建服务器（§5.0.8）
7. **商业化场景（预留）**：未来高级功能（如更大同步容量、云回收站、AI 高级模型）按 tier 开放，免费用户功能不受影响

## 5. 功能需求

### 5.0 Phase 0：WebDAV 自用过渡（P0，先行开发）

#### 5.0.1 定位与边界

- **定位**：自用阶段的完整同步方案，0 成本、0 服务器、0 备案、0 运维
- **边界**：不承载账号体系；认证 = 坚果云 WebDAV 授权码（Basic Auth）；将来商业化时整个 Phase 0 通道下线，数据经迁移工具转移（§5.0.8）
- **坚果云免费版能力基线（2026-08 核实）**：5GB 空间、每月 1GB 上传 / 3GB 下载流量、WebDAV 开放协议、增量同步、无限文件历史版本

#### 5.0.2 可插拔同步架构

- 定义接口 `ISyncProvider`，方法：
  - `Push(changes)` 增量推送 `[{id, content, tags, updatedAt, deleted, deviceId, schemaVersion}]`
  - `Pull(since)` 增量拉取（返回变更 + 最新时间）
  - `Full()` 全量导出（新设备/重置用）
- 两个实现：
  - `WebDAVProvider`（Phase 0）：操作坚果云 `dav.jianguoyun.com/dav/FocusCapture/` 目录（§5.0.5）
  - `ServerProvider`（Phase 1-4）：对接 §5.5 REST API（§5.3）
- **频率策略由 Provider 上报**（如 WebDAV 上报"30 分钟 ≤600 次、单次 ≤200 文件"），引擎据此自动选择合并窗口与轮询间隔，不写死

#### 5.0.3 笔记数据格式与打包存储

**格式统一是第二层契约**：WebDAV 阶段云端存 JSON 文件、服务器阶段存 JSON 行，字段完全一致。

```json
{
  "schemaVersion": 1,
  "id": "a1b2c3d4...",             // 确定性哈希：SHA256(相对路径 + "|" + 行内容) 前 16 字节 hex
  "content": "base64 密文",          // E2EE 加密后的内容（§5.0.7）
  "tags": ["密文数组"],
  "createdAt": "2026-08-12T00:00:00Z",
  "updatedAt": "2026-08-12T00:00:00Z",
  "deleted": false,
  "deviceId": "pc-main"
}
```

- **笔记 ID = 确定性哈希（v0.3.1 修正，替代 GUID）**：本地笔记是 MD 行（无稳定 GUID），故 ID = `SHA256(相对 NotesPath 路径 + "|" + 完整行内容)` 前 16 字节 hex。**同一行在任何设备生成相同 ID → 天然幂等、天然去重、无需索引表**；编辑追加新行 = 新 ID（与 v2.0"MD 只增不减"语义契合），旧行在下次解析不再存在即软删。（v0.3.2 澄清：**"行内容" = 完整原始 MD 行，含 `- [yyyy-MM-dd HH:mm] ` 时间戳前缀**，禁止剥离时间戳后的纯内容——否则同一文件内两条相同内容会撞 ID，被同步去重合并丢一条）
- `schemaVersion`：格式演进版本号（将来加附件/结构化 tag 时兼容迁移，**现在就带**）
- **打包存储（关键决策，防文件粒度撞墙）**：坚果云单次同步 >200 文件触发 503。**禁止"每条笔记一个文件"**，改为按**数量桶**（每 200 条一个）或**时间桶**（每周一个）合并为 `notes-{bucket}.json`，桶内为 JSON 数组。一次同步只操作几个桶文件，笔记量增长不增加请求数
- 桶拆分规则：优先按 `updatedAt` 周份分桶；桶内超 200 条自动按 ID 排序拆半。删除的笔记保留软删标记驻留桶内（轻量），全桶清理见 §5.0.6
- 云端同目录另存一个 `sync_meta.json`（E2EE 盐 + 桶清单 + 同步游标）：盐明文（无需保密，跨设备一致的关键），桶清单用于 push 后清理孤儿桶

#### 5.0.4 同步引擎（设备自述 / 冲突 / 自愈）

| 机制 | 规则 |
|---|---|
| **device_id 回声识别** | 每台设备启动时生成唯一 `deviceId` 并持久化。每条笔记带"最后修改设备"。引擎据此区分"这是我推上去的"与"别人推上来的"，**防止 A 推 → B 拉 → B 又推的死循环**。这是增量同步不炸的前置条件 |
| 冲突策略 | last-write-wins：以 `updatedAt` 较大者为准；被覆盖方由**本地**保留旧版本快照（`prev_content`），不丢数据（云端 WebDAV 无快照能力，快照落在本地；服务器阶段快照在云端 notes 表，两阶段不冲突） |
| 同步自愈后门 | 设置页「重置同步状态」：清空本地同步游标 → 全量 `Full()` 对比 → 重新对齐。用于重装系统/本地库损坏/游标丢失后的收敛手段 |
| 本地事实源声明 | **本地 MD 文件体系是唯一事实源，云端只是传输镜像**。引擎永远以本地 `NotesPath` 下 .md 文件为准组织 push/pull 结果，云端数据仅用于对账与恢复 |

- **push 全量对账（v0.3.2 补充）**：WebDAV 无服务端游标、桶为整桶覆盖语义，push 前必须按 `sync_meta.json` 桶清单 **GET 全部云端桶**作为合并基础，本机变更按 ID 覆盖后重组整桶上传——防止"本机增量合并"漏掉他端新笔记、整桶覆盖抹掉他端数据。双端并发 push 为读-改-写非原子（最后写者赢），自用低并发可接受，记录为已知风险

#### 5.0.5 WebDAV Provider 与频率策略

- **配置项**（同步设置 UI）：服务器地址（默认 `https://dav.jianguoyun.com/dav/FocusCapture/`）、账号（坚果云邮箱）、授权码（坚果云"第三方应用管理"生成的应用密码，非登录密码）。**首次同步前 PROPFIND 目标目录，404 则 MKCOL 创建**（坚果云自定义子目录不会自动存在，v0.3.2 补充）
- **限流适配（实测数据）**：坚果云对第三方 API **30 分钟 ≤600 次请求**、**单次同步 >200 文件触发 503**。频率策略必须克制：

| 动作 | Phase 0 策略 | 原理 |
|---|---|---|
| 推送 | 变更后**合并 30 秒窗口**：1 分钟内改 10 条 = 攒成 1 次请求批量上传 | 避免"每改一条打一次"的奢侈频率 |
| 拉取 | 启动时拉 1 次 + **每 30 分钟轮询** 1 次 | 不搞实时 |
| 日请求量 | 活跃 12h ≈ 150-200 次/天 | 远低于 600 次/30 分钟红线，留 3 倍余量 |
| 触发 503 | 指数退避重试 30s/2min/10min，连续 3 次失败停止自动重试，UI 显示失败原因 | 防死循环 |

- **打包存储联动**：单次请求文件数 ≤200 由桶大小保证（§5.0.3），与频率策略共同构成限流防线
- **频率是渠道属性**：切到自建服务器（无此限制）后，合并窗口 30s→3s、轮询 30min→1min，一行配置，引擎零改动

#### 5.0.6 本地兜底与回收站

- **本地明文兜底（E2EE 的前提铁律）**：本地 MD 文件体系 **不加密**（或仅 Windows DPAPI 本机保护），E2EE 只加密"上传到云端的那份副本"。**本地永远是最后保险**——主密码丢失不影响本地数据（§5.0.7 密钥重置流程依赖此条）
- **本地回收站（产品级，优先于同步开发）**：
  - 删除笔记 → 进本地回收站（保留 N=30 天，可配置）
  - 回收站内可恢复；**确认清空才物理删除 + 同步软删标记**
  - 同步拉取到"软删"的笔记 → 进本地回收站（可恢复），不直接物理删除
  - 理由：**同步是镜像不是备份**，无回收站则误删会传染所有设备
- **删除闭环**：云端桶内软删笔记在清空回收站时从桶文件移除并重写桶
- **先写回收站后删行（v0.3.2 补充）**：删除操作必须"回收站记录写成功 → 才从原文件移除行"，写失败中止删除——防"行已删但回收站没记"的数据永久丢失（本地明文兜底铁律的具体化）

#### 5.0.7 E2EE 客户端加密（用户 2026-08-12 确认采用）

**目标**：云端（坚果云/服务器）只见密文，密钥永不上传。

**密钥体系**：

```
主密码（用户记忆）
  └─ PBKDF2（高迭代 + 随机盐 e2ee_salt）→ 数据密钥 DEK
        └─ 加密每条笔记 content/tags（AES-256-GCM）
```

- **多端密钥分发**：每台设备首次配置时输入**同一个主密码**，各自本地派生 DEK。**盐必须跨设备一致**：盐由首配设备随机生成（16 字节），**明文存云端 `sync_meta.json`**（盐无需保密，明文上传不泄露数据），后续设备首次配置先拉取盐再派生同一 DEK。DPAPI 每机不同不构成障碍——密钥来自主密码 + 盐，而非本机
- **恢复码（recovery code）**：设置主密码时生成 **14 位混合字符恢复码**（大写 + 小写 + 数字，剔除易混淆 `0/O/1/I/l`；v0.3.2 从 10 位纯数字提升——10^10 空间即使加盐 SHA-256 仍可被 GPU 暴力枚举），加盐哈希存本地，忘主密码时可用恢复码重置；**规则：恢复码不得与主密码存在同一处**

**忘密码 ≠ 废账户（两层凭证分离）**：

| 凭证 | 管什么 | 忘了会怎样 |
|---|---|---|
| 坚果云账号/授权码（或服务器账号） | 打开云端"保险箱" | 可找回，账户永存 |
| E2EE 主密码 | 解"保险箱里的密文" | 旧密文永久不可解，**但账户本身没事** |

**密钥重置流程**（用户 2026-08-12 确认的兜底路径）：

```
忘记主密码
  → 客户端提示"云端数据无法解密"
  → 输入新主密码 → 派生新 DEK
  → 客户端用新 DEK 重新加密本地明文笔记
  → 全量覆盖上传（覆盖旧密文）
  → 多端同步恢复
```

- **跨设备盐同步（v0.3.2 补充）**：重置生成新盐后，其他设备本地缓存的旧 `E2eeSalt` 派生 DEK 解新密文必失败；客户端须在解密失败时比对"云端 `sync_meta.json` 盐 vs 本地缓存盐"，不一致则提示"云端密钥可能已被重置，请重新输入主密码并刷新盐"，引导重拉盐后重新派生 DEK——不得静默当"数据损坏"处理
- **前提**：本地明文兜底（§5.0.6）保证"本地在，数据就在"
- **唯一真实损失**：仅存在于云端、未同步到任何本地设备的数据（自用多端配同一主密码，概率极低）
- **安全边界**：E2EE 下服务端/坚果云**不做内容加密**（客户端密文已覆盖），传输层 HTTPS 保留；原"服务端加密存储"设计取消（冗余）

#### 5.0.8 迁移到商业化（切换时刻状态机）

- **原则**：迁移是"切换时刻"，不是"导数据"——防止双通道并发写冲突
- **状态机**（客户端内置迁移工具，用户零手工操作）：

```
关 WebDAV 同步 → 全量导出（本地 → 完整 JSON 包）
  → 注册/登录自建服务器 → 全量导入（JSON 包 → 服务器 API）
  → 开启 Server 同步 → 校验两端口径一致 → 完成
```

- 任一步失败可回退：导出包留存本地，随时重试；未完成前 WebDAV 配置保留但**不运行**（避免双写）
- 迁移完成后 WebDAV Provider 下线，坚果云数据可留作冷备份或手动清理

### 5.1 账号体系（P0，Phase 1-4 商业化目标态）

#### 5.1.1 注册

- 字段：**邮箱 + 密码 + 昵称**（昵称可选，默认取邮箱前缀）
- 校验：邮箱格式合法；密码 ≥ 8 位（含字母+数字）；昵称 ≤ 12 字符
- 密码存储：**Argon2id**（或 bcrypt）哈希，数据库禁止明文
- 邮箱唯一性：重复注册返回明确错误
- 不做：邮箱验证、验证码

#### 5.1.2 登录 / 退出

- 邮箱 + 密码登录，成功返回 JWT Access Token（有效期 30 天）+ 用户信息
- 登录失败（密码错误/账号不存在）返回统一错误文案，不泄露账号存在性
- 退出登录 = 本地清除 token（服务端无状态，JWT 无吊销，可接受）

#### 5.1.3 登录态保持

- Token 存本地，**Windows DPAPI 加密后**写入 `%AppData%\FocusCapture\settings.json`
- 启动时解密校验：token 有效 → 静默恢复登录态；过期 → 提示重新登录（不自动登出其他设备）

#### 5.1.4 改密码

- 登录状态下输入旧密码 + 新密码，校验旧密码后更新哈希
- 修改后本地 token 续期，其他设备需重新登录（JWT 无吊销，靠 30 天过期兜底，已确认可接受）
- **注意**：账号密码与 E2EE 主密码是两个独立密码（§5.0.7），改账号密码不触发 E2EE 密钥变更

#### 5.1.5 找回密码（P1，用户 2026-08-12 确认做）

- 入口：登录窗口「忘记密码」链接
- 流程：输入邮箱 → 服务端生成 **6 位数字验证码**（哈希存储）→ SMTP 发邮件 → 用户输入验证码 + 新密码 → 校验通过更新密码哈希
- 验证码规则：10 分钟有效、一次性（用后即焚）、同邮箱 10 分钟内限发 1 次
- 限流：`forgot-password` 接口同 IP 每小时 ≤5 次，防枚举
- 邮件发送：SMTP 客户端（QQ 邮箱 465 SSL 起步），发件配置走服务器环境变量（`SMTP_HOST/PORT/USER/PASS`），不硬编码

#### 5.1.6 主页入口改造（悬浮球右键菜单）

| 登录状态 | 菜单显示 | 行为 |
|---|---|---|
| 未登录 | 项「登录」 | 打开登录/注册窗口 |
| 已登录 | 项「主页」+ 昵称（≤10 字符，超长截断） | 打开主页窗口 |

- 主页窗口（ProfileWindow）：账号信息区 + 同步管理区（见 5.3）
- 登录成功后悬浮球菜单即时刷新（沿用 v2.0 `UpdateAiName` 同款即时同步模式）

### 5.3 云端同步（P0，Phase 1-4 商业化目标态）

#### 5.3.1 同步协议四要素（与 Phase 0 同源，引擎复用）

| 要素 | 规则 |
|---|---|
| 笔记 ID | **GUID 全局唯一**，客户端生成，多端/多用户天然不冲突 |
| 变更追踪 | 每条笔记带 `updatedAt`（UTC 时间戳），增量依据 |
| 删除传播 | **软删标记** `deleted`（不物理删除），拉取端见标记即进本地回收站（§5.0.6） |
| 冲突策略 | **last-write-wins**：以 `updatedAt` 较大者为准；被覆盖方由服务端保留旧版本快照（云端 notes 表 `prev_content` 字段），不丢数据 |

#### 5.3.2 同步接口（REST，Server Provider 使用）

| 接口 | 说明 |
|---|---|
| `POST /api/sync/push` | 批量推送变更 `[{id, content, tags, updatedAt, deleted, deviceId}]` → 返回服务端最新时间 |
| `GET /api/sync/pull?since={ts}` | 增量拉取 `since` 之后变更 + 服务端最新时间 |
| `GET /api/sync/full` | 全量拉取（新设备首次登录/数据恢复用） |

- 幂等：push 按 id + updatedAt 幂等，重复推送不产生重复数据
- 分页：单次 pull 超过 500 条分页（返回 `nextSince`）

#### 5.3.3 同步触发（频率渠道化）

| 触发方式 | Phase 1-4（自建服务器） | Phase 0（WebDAV，见 §5.0.5） |
|---|---|---|
| 手动 | 主页「立即同步」按钮，强制 push + pull | 同 |
| 自动（可开关） | 笔记变更后 **3s** 静默推送；启动时 + 每 **1 分钟**轮询 pull | 变更后 **30s 合并窗口**推送；启动时 + 每 **30 分钟**轮询 |
| 失败重试 | 网络失败静默重试，退避 30s/2min/10min 三档；连续失败 3 次后不再自动重试，UI 显示"上次同步失败 + 原因"，等手动 | 同（另含 503 专项退避，§5.0.5） |

#### 5.3.4 同步与本地解耦（铁律）

- **本地为主、云端为镜像**：断网/未登录时工具功能 100% 可用，同步永远后台跑
- 同步不得阻塞/影响捕捉、速览、语音等主流程
- 未登录/未配置 WebDAV 用户无同步能力，本地功能不受任何影响

#### 5.3.5 删除规则

| 操作 | 本地行为 | 云端行为 |
|---|---|---|
| 删除笔记 | 进本地回收站（§5.0.6，N=30 天） | 软删标记同步 |
| 清空云端数据（主页按钮） | 不影响本地 | 二次确认后真删云端全部笔记（含快照） |
| 注销账号 | 退出登录 | 真删 users + notes（含备份清理，见 §6 合规） |

### 5.4 数据模型（P0 架构）

```sql
-- users（tier 字段=商业留白，本版恒为 'free'；E2EE 下服务端不存密钥）
CREATE TABLE users (
  id           TEXT PRIMARY KEY,           -- GUID
  email        TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,             -- Argon2id（账号密码）
  nickname     TEXT NOT NULL,
  avatar_path  TEXT,
  tier         TEXT NOT NULL DEFAULT 'free',   -- 预留：free/pro
  plan_expires_at TEXT,                    -- 预留：付费到期时间
  created_at   TEXT NOT NULL
);

-- notes（同步表，多用户设计；E2EE 下 content 为客户端密文 Base64）
CREATE TABLE notes (
  id             TEXT PRIMARY KEY,         -- 客户端确定性哈希（SHA256 路径+行内容，§5.0.3）
  user_id        TEXT NOT NULL,
  content        TEXT NOT NULL,            -- 密文（E2EE）
  tags           TEXT,                     -- 密文 JSON 数组（E2EE）
  prev_content   TEXT,                     -- 冲突时被覆盖的旧版本快照（密文）
  device_id      TEXT,                     -- 最后修改设备（回声识别，§5.0.4）
  schema_version INTEGER NOT NULL DEFAULT 1,
  created_at     TEXT NOT NULL,
  updated_at     TEXT NOT NULL,
  deleted        INTEGER NOT NULL DEFAULT 0
);

-- password_resets（找回密码验证码）
CREATE TABLE password_resets (
  id         TEXT PRIMARY KEY,
  user_id    TEXT NOT NULL,
  code_hash  TEXT NOT NULL,               -- 6 位数字验证码哈希
  expires_at TEXT NOT NULL,               -- 10 分钟有效
  used       INTEGER NOT NULL DEFAULT 0
);
```

**本地侧（客户端，唯一事实源）**：MD 文件体系（`NotesPath`，明文，行格式 `- [yyyy-MM-dd HH:mm] 内容 — 来源: xxx`）+ sidecar 同步状态 `sync_state.json`（同步游标 + deviceId + Provider 配置 + e2ee_salt + recovery_code_hash）+ 回收站区 `.recycle_bin/`（30 天）。云端桶 JSON 只是传输镜像，非本地存储形态。

> 注：v0.2 曾假设本地用 SQLite 承载同步状态；v0.3.1 修正——本地保持 MD 文件体系不动（v2.0 只增不减铁律），同步元数据走 sidecar JSON。**服务端**的 SQLite（Phase 1-4）不受影响。

- 服务端 **EF Core + SQLite** 起步（单文件，备份=复制文件）；将来商业化切 PostgreSQL 只改 Provider + 连接串
- 代码分层 Controller → Service → Repository，users 模块将来扩展（找回密码/验证码/配额）为增量新增，非重构

| 项 | 要求 |
|---|---|

| 离线 | 断网时全部本地功能可用，同步静默失败重试 |
| 兼容 | 延续单文件绿色版分发（WPF .NET 8 self-contained） |
| 部署 | Docker 单容器（API + SQLite 数据卷 + 头像目录挂载）；迁移=复制 compose + 数据卷 |

## 9. 验收标准

### 9.1 Phase 0 验收（自用标准，3 条主 + 细节项）

1. 主力电脑记的笔记，第二台电脑配置同一坚果云 WebDAV 后能看到（≤30 分钟延迟）；第二台改完，主力电脑同步回来
2. 其中一台断网，另一台完全不受影响；恢复联网后自动补齐（不重复、不丢）
3. 坚果云网页端查看云端文件：**内容为密文**（E2EE 生效），主密码正确时客户端可正常解密
4. 打包存储生效：云端为桶 JSON 文件（非每条一个文件）；单次同步文件数 ≤200
5. 回声识别生效：A 推 → B 拉 → B 不再重复推送（无死循环）
6. 本地回收站：删除进回收站 → 30 天内可恢复；清空回收站 → 云端软删同步；误删场景数据可找回
7. 密钥重置：忘记主密码 → 新主密码重新加密 → 全量重传 → 双端恢复；恢复码可解锁
8. 同步自愈：损坏/删除本地同步游标后，「重置同步状态」可全量重新对齐
9. 连续 3 次同步失败后停止自动重试，UI 显示失败原因；手动「立即同步」可恢复

### 9.2 Phase 1-4 验收（商业化标准）

1. 邮箱+密码可注册/登录；重复邮箱注册被拒；密码 ≥8 位含字母数字；数据库无明文密码（查库验证哈希）
2. 登录态跨应用重启保持（token DPAPI 持久化）；token 过期后提示重登
3. 第二台设备登录同一账号 → 全量拉取全部笔记；第一台新增/编辑/删除 → 第二台增量同步后一致
4. 同步幂等：重复 push 不产生重复数据；断网重连后自动补齐
5. 冲突场景：两端同时改同一笔记 → 保留较新者，被覆盖旧版本在云端 `prev_content` 可查，本地不丢数据
6. 主页：可改昵称/头像（≤1MB）/改密码/退出登录；「清空云端」二次确认后云端笔记清零、本地不受影响
7. 自动同步开关生效；连续失败 3 次停止自动重试，主页显示失败原因与上次同步时间
8. 未登录用户全部本地功能可用，界面无同步干扰；登录入口只在悬浮球右键菜单
9. 找回密码：忘记密码 → 邮箱收到 6 位验证码 → 输入验证码 + 新密码可登录；验证码 10 分钟过期、二次使用无效；同邮箱 10 分钟内重复请求被限流
10. users.tier 字段存在且恒为 'free'，SQLite 换 PostgreSQL 仅改连接配置
11. 部署后 HTTPS 访问正常；登录/找回密码接口限流生效（同 IP 高频请求被拒）
12. 迁移工具：Phase 0 → 服务器切换按状态机执行，任一步失败可回退，双通道无并发写

## 附：方案对比与演进说明

**为什么选"WebDAV 优先 + 可插拔"，而非一步到服务器（2026-08-12 二次讨论结论）**：

| 方案 | 成本 | 运维 | 将来商业化 |
|---|---|---|---|
| 坚果云 WebDAV（Phase 0 采用） | 0 元 | 无服务器/备案/运维 | **不废弃**：换 Provider 实现，其余全复用 |
| Git 私有仓库 | 0 元 | 无，但冲突处理是文件级、实时性差 | 基本废弃（仅留数据），不采用 |
| 自建轻量服务器（Phase 1-4 采用） | ~125-150 元/年 + 备案 | 补丁/备份/监控 | 目标态：账号体系一步做对 |

方案 A（单 Token 无账号）在 v0.2 即被放弃（用户确认要做账号体系）；v0.3 又新增 WebDAV 作为 Phase 0，账号体系（方案 B）保留为 Phase 1-4 目标态——**两阶段共用同一客户端同步架构，切换只换 Provider + 一次数据迁移**。

**E2EE 与"服务端加密"取舍**：v0.2 曾计划"服务端加密存储"（密钥在服务器，可找回）。用户确认采用 E2EE 后，服务端内容加密设计取消（客户端密文已覆盖），代价是忘主密码 = 云端密文永久不可解，由"本地明文兜底 + 密钥重置流程"对冲（§5.0.7）。
