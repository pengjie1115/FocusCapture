## 4. 步骤 0 成果：`config init --new` 真实输出（实测真值，已验掉）

上一会话写了独立探针 `tools/depdiag/`（参考 `tools/clipdiag/`，独立 csproj，不引用主项目），在隔离 USERPROFILE + 清 HERMES_HOME/OPENCLAW_HOME/LARK_CHANNEL/PYTHONPATH 下跑 `lark-cli config init --new`，90s 超时 kill 保留已读。

**5 条硬事实**：

1. **全走 stderr，stdout 空**（0 行）；不是 JSON，是纯文本 + ASCII 块二维码 + URL
2. 结构：`[ASCII 码] / 打开以下链接配置应用: / <空行> / https://open.feishu.cn/page/cli?user_code=XXXX-XXXX&lpv=<cli版本>&ocv=<版本>&from=cli / <空行> / 等待配置应用...`
3. **流式、启动约 1 秒吐完**，然后阻塞等浏览器完成
4. URL 形如 `https://open.feishu.cn/page/cli?user_code=<8位含连字符>&lpv=<cli版本>&ocv=<版本>&from=cli`
5. **超时 kill 保留全部已读**（stderr 29 行 + URL）—— **R1 验证通过**

**对实现的 3 点修正**：
- ① 解析不是 JSON，是从 **stderr 纯文本**用正则提取 `https?://` URL
- ② 流式读到 URL 即提取显示，**但命令不能 kill** —— 要持续运行到用户浏览器完成才自然退出（user_code 是设备码流，kill 掉没主体接收、配置写不进）
- ③ 乙方案第一步 `config init --new` 产物是**浏览器链接**（非扫码）；二维码在第二步 `auth login`

**附带收获（--help 实测）**：
- 命令自带 `Risk: write`（非 high-risk-write，不需 `--yes`）
- help 原文坐实 R1 阻塞语义：`use --new to create a new app. The command blocks until the user completes setup in the browser. Run it in the background and retrieve the verification URL from its output.`
- lark-cli 区分独立 CLI 模式 vs Agent 宿主模式（OPENCLAW_HOME/HERMES_HOME 存在时 `--new` 默认拒绝→要用 `config bind`）。**清掉宿主变量 → 走独立模式 → 印证清变量的正确性**

**复现探针**（验证用）：

## 5. 步骤 1 改造方案 + 影响面（R1/R2/R3，**已侦察完，未改代码**）

> **红线 4：改代码前先做影响面评估，交用户定夺后再动手。** 本节就是影响面评估，动手前先把本节方案跟用户过一遍。

### 5.1 R1：`SkillProcess.RunAsync` 流式读 + 超时保留已读

**病根（`Services/Skills/SkillProcess.cs:101-148`）**：
- 用 `proc.StandardOutput.ReadToEndAsync()` / `ReadToEndAsync()` —— 等流结束（进程退出）才完整拿到
- 超时分支（`:142`）`return new ProcessResult(-1, "", "", true, null)` —— **stdout/stderr 全丢空字符串**，`stdoutTask`/`stderrTask` 已读的内容被丢弃

**后果**：阻塞命令（如 `config init --new`）进程不退出 → `ReadToEndAsync` 不完成 → URL 永远拿不到；超时连已读都丢。

**改造方向**：
- 改成按行流式读（`OutputDataReceived`/`ErrorDataReceived` + `BeginOutputReadLine`/`BeginErrorReadLine`），每行累积到 `StringBuilder`/`List<string>`
- **超时分支保留已读内容**：kill 后把已累积的 stdout/stderr 填进 `ProcessResult`（不是传 `""`）—— 这一条是现有 10 个调用点都受益的最小改动
- **新增流式抓取能力**（给授权层 `config init --new` 用）：设计稿 R1 处置写"按行/按标记读到 URL 即返回，或超时 kill 但保留已读"。**关键约束（来自 §4 真值）**：`config init --new` 抓到 URL 后**不能 kill**，要持续运行到用户浏览器完成才自然退出。所以新 API 形态应是"流式回调（读到行就回调）+ 进程继续运行 + 调用方决定何时取消/等退出"，**不是"抓到 URL 就 kill"**

**调用点（10 处 `SkillProcess.RunAsync`，全要兼容）**：
- `SkillScriptRunner.cs:169`（跑脚本，要 stdout+stderr+退出码三段）
- `SkillDependency.cs:145` ProbeAsync（`auth status`）
- `SkillDependency.cs:215` StartAuthAsync（`auth login --no-wait --json`，非阻塞，取 stdout JSON）
- `SkillDependency.cs:255` MakeQrPngAsync（`auth qrcode`，取产物文件）
- `SkillDependency.cs:278` CompleteAuthAsync（`auth login --device-code`，会阻塞轮询）
- `SkillDependency.cs:292` LogoutAsync（`auth logout`）

**注意**：`StartAuthAsync` 现在用 `r.Stdout` 解析 JSON（`:220`），但**实测 lark-cli 的 JSON 输出走 stderr**（设计稿 §2.3）。`auth login --no-wait --json` 的 device_code JSON 是否也走 stderr —— **本会话没验**，实现时要先跑一次确认（用探针 `--args "auth login --no-wait --json"`，注意这会真发起授权）。

### 5.2 R2：`SkillScriptRunner.BundledPathPrefix()` 只前置自带目录

**病根（`Services/Skills/SkillScriptRunner.cs:255-265` `BundledPathPrefix`）**：
- 只遍历 `_dependencies` 的 `dep.BundledDir`（自带目录），按需下载后的 AppData 目录不在列
- 脚本里 `shutil.which("lark-cli")` 找不到 → 桥接脚本失效

**改造方向**：把"所有候选目录都前置"——自带目录 + 数据目录（AppData）。需要 `SkillDependency` 暴露"候选目录列表"（自带 + 数据目录），`BundledPathPrefix` 全部前置。

**`BundledDir` 调用点（6 处）**：
- `SkillDependency.cs:100` 定义（`_bundledDir = Path.Combine(baseDir, "runtime", id)`，固定自带目录）
- `SkillScriptRunner.cs:261`（BundledPathPrefix 用）
- `Windows/SettingsWindow.xaml.cs:434-435`（判断 `ExePath` 是否在 `BundledDir` 下，显示"自带"标记 —— **改候选列表后这里也要同步**）
- `tests/sync/Program.cs:248-249`（检查点断言 —— 改后要同步更新，否则检查点红）

### 5.3 R3：`SkillRuntime` 的 Python 路径固定拼接

**病根（`Services/Skills/SkillRuntime.cs:27`）**：

**改造方向**：候选路径列表（自带 `baseDir\runtime\python\` + AppData `…\runtime\python\`），依次找存在的。`PythonPath` / `IsPresent` / `QuickStatus` / `ProbeAsync` 都要改成走候选。

## 7. 环境坑（本项目实测过）

- **PowerShell 侧 git 出不了网**（退 128 且零输出）→ push / ls-remote 一律走 bash
- 写文件工具会"报成功但没写入" → 落笔后必须 Grep 复核；**同一文件一轮里多个 Edit 必须串行**
- bash 侧 coreutils 全灭（`ls`/`find`/`cat`/`grep` 全 127）→ 探测走 PowerShell，结果落 `%TEMP%` 文件再读
- **`Start-Job` / `Process.Start` 被沙箱拦**（指沙箱内脚本/cmdl 起进程）→ 需要起进程的探针写成项目内独立 csproj（参考 `tools/clipdiag/`、`tools/depdiag/`）。**但独立编译 exe 起子进程正常**（步骤 0 已验证）
- 编译前补 `APPDATA` / `PROGRAMFILES` / `ProgramW6432` / `ProgramData`（或直接用 `dev.ps1 build`，它自带补丁）
- `.bat` 不能含中文；`git commit` 传中文要用 `-F <utf8 文件>`
- `runtime\` 在 `.gitignore`；`builtin-skills\` **必须进仓库**（与 runtime 相反）
- 读环境变量只能用 `[System.Environment]::GetEnvironmentVariables()` —— `Get-ChildItem Env:` 在本沙箱返回空
