## 1. Agnes（中国站）

- **BaseUrl**：`https://apihub.agnes-ai.cn/v1`
- **端点**：`GET https://apihub.agnes-ai.cn/v1/models` —— ✅ 存在（401 实测）
- **返回结构**：⚠️ **未验证（推测）**。官方文档（Overview 页）**通篇没有 `/models` 端点**，也没有 list models 页面。只能推测是 OpenAI 标准结构：`{"object":"list","data":[{"id","object","created","owned_by"}]}`。
- **能力字段**：⚠️ 无官方证据。推测**不含** `context_length`。
- **鉴权**：`Authorization: Bearer <key>`（一手，官方 Overview 页明确）。
- **错误格式**：实测 401 为 `{"error":{"code":"","message":"Token not provided ...","type":"AgnesAI_error"}}`；`type` 固定 `AgnesAI_error`，`code` 为空串。其他状态码未见官方错误码表。
- **分页**：未知，推测无。
- **权限门槛**：注册即可用；免费用户有速率限制（第三方称约 20 RPM）。
- **⚠️ 区域路由矛盾（保留不平滑）**：
  - 官方 GitHub（AgnesAI-Labs/skills）称：国际主站 `https://apihub.agnes-ai.com/v1`；国际备用 `https://apihub.agnes-ai.cn/v1`；**中国服务 `https://api.agnes-ai.cn/v1`**。
  - 中文博客/资讯则称 `https://apihub.agnes-ai.cn/v1` 就是**国内站**。
  - 结论：本项目采用的 `apihub.agnes-ai.cn` 端点实测可连通（401），可用；但「它到底属于哪个区域」两种说法冲突，未定论。
- **来源**：
  - 一手：官方 Overview（`https://www.agnes-ai.com/en/docs/overview`）——只证实 BaseUrl/Bearer，未覆盖 /models。
  - 二手（官方 GitHub 组织）：`https://github.com/AgnesAI-Labs/skills/blob/main/agnes-ai-models/SKILL.md`、`https://github.com/AgnesAI-Labs/Agnes-AI/blob/main/MODEL_CATALOG.md`
  - 实测：本项目 curl 探测。

## 2. DeepSeek

- **BaseUrl**：`https://api.deepseek.com/v1`
- **端点**：官方文档写 `GET https://api.deepseek.com/models`（**不带 /v1**）；实测 `https://api.deepseek.com/v1/models` 也返回 401 → **两种拼法都通**。本项目 BaseUrl 已含 `/v1`，拼 `/models` = `/v1/models`，✅ 成立。
- **返回结构**（一手，官方 API 文档）：
  ```json
  {
    "object": "list",
    "data": [
      { "id": "deepseek-v4-pro", "object": "model", "owned_by": "deepseek" }
    ]
  }
  ```
  元素字段：`id`、`object`("model")、`owned_by`。**没有 `created`**。
- **能力字段**：❌ **没有** `context_length` / `max_tokens` 等任何能力字段（一手文档确认，官方 schema 只有上述三个字段）。
- **鉴权**：`Authorization: Bearer <key>`（一手）。
- **错误格式**：
  - 一手（官方错误码页）：只给了状态码含义，**未给 JSON body 示例**：`400` 格式错误 / `401` 认证失败 / `402` 余额不足 / `422` 参数错误 / `429` 速率上限 / `500` 服务器故障 / `503` 服务器繁忙。
  - 二手（第三方 API 文档站 + CSDN 实测日志）：body 为 `{"error":{"message":"...","type":"...","param":null,"code":"..."}}`，401 例：`{"error":{"message":"Authentication Fails, Your api key: **** API is invalid","type":"authentication_error","param":null,"code":"invalid_request_error"}}`。
  - **⚠️ 实测异常**：本次无鉴权探测得到的是**纯文本** `Authentication Fails (governor)`、`Content-Type` 为空 —— 说明 DeepSeek 前置网关（governor 层）在完全无 key 时返回的不是 JSON。解析时**不能假设错误体一定是 JSON**。
  - 429 带 `Retry-After` 头（二手）。
- **分页**：❌ 无。
- **权限门槛**：需账户有余额（402 区分于 401）。
- **来源**：
  - 一手：`https://api-docs.deepseek.com/zh-cn/api/list-models/`、`https://api-docs.deepseek.com/zh-cn/quick_start/error_codes`
  - 二手：`https://deepseeksr1.com/api-docs/`
  - 三手：`https://blog.csdn.net/wstever/article/details/160630075`（401 日志）
  - 实测：本项目 curl 探测。

## 3. 智谱 GLM

- **BaseUrl**：`https://open.bigmodel.cn/api/paas/v4`
- **端点**：`GET https://open.bigmodel.cn/api/paas/v4/models` —— ✅ 存在（401 实测）。**注意**：GLM Coding 套餐用的是另一个端点 `/api/coding/paas/v4`，官方明确「Coding 端点仅限 Coding 场景，不适用通用 API」。
- **返回结构**（**二手，实测**，两个独立来源一致）：
  ```json
  {"object":"list","data":[
    {"id":"glm-4.5","object":"model"},
    {"id":"glm-4.5-air","object":"model"},
    {"id":"glm-4.6","object":"model"},
    {"id":"glm-4.7","object":"model"},
    {"id":"glm-5","object":"model"},
    {"id":"glm-5-turbo","object":"model"},
    {"id":"glm-5.1","object":"model"}
  ]}
  ```
  元素**只有 `id` 和 `object`** —— 没有 `created`、没有 `owned_by`、没有 `context_length`。⚠️ 官方文档**未收录该端点**，故结构为二手实测，版本可能变化。
- **能力字段**：❌ **没有**。且有一个**重要坑**：实测该端点**只列出付费主力模型**，`glm-4-flash`、`glm-4.7-flash` 等免费模型**不在列表里**（两个独立来源均确认）。用户若想加免费模型，只能手填 ID。
- **鉴权**：`Authorization: Bearer <key>`，也支持 JWT 鉴权（`id.secret` 拆分后 HS256 签名，头 `Authorization: Bearer <jwt>`）（一手）。
- **错误格式**（一手，官方错误码页）：**两层结构** —— 外层 HTTP 状态码 + 内层业务 `code`：
  | 业务 code | HTTP | 含义 |
  |---|---|---|
  | 1000 / 1001 / 1003 / 1005 | 401 | 身份验证失败 / 未收到 Authorization / Token 过期 / 需二次认证 |
  | 1220 | 403 | 无权访问该 API |
  | 1210/1211/1212/1213/1214/1221/1222/1261/1301 | 400 | 参数有误 / 模型不存在 / Prompt 超长 / 内容安全等 |
  | 1113 / 1302 / 1305 / 1308 / 1309 / 1311 / 1313 | 429 | 欠费 / 速率限制 / 访问量过大 / 达上限 / 套餐到期 / 无权限 / 公平策略 |
  | 1200 / 1230 / 1234 | 500 | API 调用失败 / 流程出错 / 网络错误 |
- **分页**：❌ 未见。模型数量少，推测无。
- **权限门槛**：部分模型需套餐/权益（如 1311「当前套餐未开放该模型权限」、1220 无权访问）；通用 API 与 Coding 套餐是两套额度。
- **来源**：
  - 一手：`https://docs.bigmodel.cn/cn/guide/develop/http/introduction`（BaseUrl/Bearer/JWT）、`https://docs.bigmodel.cn/cn/faq`（错误码表）
  - 二手（实测原始响应）：`https://github.com/liliMozi/openhanako/issues/1266`
  - 三手（实测）：`http://www.rrmt.cn/news/55944`（确认 flash 模型不在 /models 里）
  - 实测：本项目 curl 探测。

## 7. 对实现的影响

### 7.1 能可靠拿到「上下文窗口」的有哪些？

| 供应商 | 能否从 `/models` 回填上下文窗口 | 依据 |
|---|---|---|
| **Kimi** | ✅ **能**（`context_length`） | 一手官方文档 |
| **通义千问** | ⚠️ 兼容模式端点**不确定**；原生 `/api/v1/models` ✅ 有（但不是本项目的 BaseUrl） | 一手（仅原生） |
| **Agnes** | ❌ 拿不到（推测无） | 无证据 |
| **DeepSeek** | ❌ 拿不到 | 一手文档确认无 |
| **智谱 GLM** | ❌ 拿不到 | 二手实测确认无 |
| **腾讯混元** | ❌ 拿不到（TokenHub 也无） | 一手文档确认无 |

**结论：6 家里只有 Kimi 能稳定自动回填上下文窗口。** 其余 5 家必须靠「用户手填 + 内置默认表兜底」。因此设计上**不能把「自动拿到上下文窗口」当成主路径**，只能是 Kimi 的增强项。

### 7.2 解析时最需要注意的差异点

1. **顶层容器字段**：目前 6 家实测/文档见的都是 `data`（未见 `models`），但仍建议**同时兼容 `data` 和 `models`** 两个顶层键，避免小众节点差异导致空列表。
2. **元素字段差异极大**（这是最容易写崩的地方）：
   - 最全：Kimi（`id`/`object`/`created`/`owned_by`/`context_length`/`supports_*`）
   - 标准：DeepSeek、DashScope 兼容、Agnes
   - **残缺**：智谱只有 `id`+`object`（**没有 `created`/`owned_by`**）→ 若代码 `model.owned_by` 直接取值会 NRE/空显示，**必须全部按可选字段处理**。
   - **异构**：腾讯 TokenHub 是 `id`+`object`+`name`+`created`+`status`（**没有 `owned_by`，多了 `name`/`status`**）→ 展示名可用 `name ?? id`，且可用 `status=="online"` 过滤下线模型。
   - 因此：**模型 ID 只认 `id`；显示名取 `name ?? id`；`owned_by`/`created`/能力字段全部当可选**，缺失时静默降级，绝不抛异常。
3. **能力字段命名不统一**：上下文窗口在不同来源可能叫 `context_length`（Kimi）、`context_window`（百炼原生，但那是查询参数）、或完全缺失。解析侧应写成「依次尝试 `context_length` → `context_window` → `max_context_length` → `max_input_tokens`，取第一个能转成 int 的正数，否则返回 null」。

### 7.3 鉴权与错误分类

- **鉴权**：6 家**全部**是标准 `Authorization: Bearer <key>`，无额外头、无需 API 版本路径（智谱也支持 JWT，但 Bearer 足够）。这一条可统一实现。
- **错误分类建议**（用 HTTP 状态码为主，业务码为辅）：
  - **Key 无效**：`401`（通用）；智谱看内层 `code ∈ {1000,1001,1003,1005}`；Kimi 看 `error.type == incorrect_api_key_error`；腾讯看 `code == invalid_api_key`。
  - **无权/未开通**：`403`（智谱 `1220`）；百炼 403 也可能是余额/未开通服务。
  - **余额不足**：DeepSeek `402`；智谱 `429` 里的 `1113`（欠费）—— ⚠️ **智谱把「欠费」放在 429 里**，不能只按状态码区分。
  - **限流/暂时不可用**：`429`（智谱有 1113/1302/1305/1308/1309/1311/1313 多个业务码）、`500`/`503`（DeepSeek、智谱 1200/1230/1234）。`429` 若能读到 `Retry-After` 就尊重它。
  - **本机网络不通**：无 HTTP 响应（超时/DNS/TLS 失败）→ 与上面所有「有响应」的情况区分开。
  - **⚠️ 错误体不保证是 JSON**：DeepSeek 无鉴权时返回纯文本 `Authentication Fails (governor)`、`Content-Type` 为空。**解析错误体必须先 try-catch JSON，失败则退化为「HTTP 状态码 + 原始文本片段」**，不能直接 `JsonSerializer.Deserialize` 后访问属性。
- **业务错误码的读取位置也不统一**：智谱在 `error.code`（字符串数字）、百炼原生在顶层 `code`、Kimi 在 `error.type`、腾讯在 `error.code`。建议做一层「多路径探取 code/type/message」的容错提取。

### 7.4 分页与其它

- **分页**：只有百炼原生 `/api/v1/models` 有（`page_no`/`page_size`，默认 20）。**OpenAI 兼容的 `/models` 一律返回全量，无需翻页**。本项目若只打 `{BaseUrl}/models`，可**不做分页逻辑**。
- **智谱坑（要写进 UI 提示）**：`/models` **不返回免费 flash 系列**，用户会以为「拉不到免费模型」→ 应支持「拉取后手动补加模型 ID」。
- **腾讯坑**：旧域名 `api.hunyuan.cloud.tencent.com` 仍是可用但属**迁移前**的端点；官方新方案是 TokenHub（`tokenhub.tencentmaas.com`），BaseUrl 与 Key 体系不同、**Key 不可跨平台混用**。建议在供应商预设里把两者当两个可选项，而不是自动互换。
