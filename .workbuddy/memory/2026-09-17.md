## 事故：一个未跟踪文件在合并过程中丢失（如实记录）

**丢的是**：`docs/悬浮球拖放-开发提示词.md`（用户给我的开工提示词文档，**从未提交过 git**）。
切分支前它还是 `??` 未跟踪状态，合并流程走完后**磁盘上已经没有这个文件**（`**/*提示词*` 全局搜不到）。

### 已排除的可能（都有证据）

| 可能性 | 查证结果 |
|---|---|
| 被 .gitignore 忽略 | `git check-ignore -v` 退出码 1 → **未忽略** |
| 曾进过 git、可从历史恢复 | `git log --all -- docs/` 全量列提交，**没有任何一条涉及该文件** → 从未入库，git 救不回 |
| 进了回收站 | git 的删除是 unlink，**不走回收站**；未做进一步验证（去了也白去） |
| 被 `git add -A` 之类误提交/误删 | 本会话全程**显式列路径** add，未用通配符 |

### 关键实验（为定位机制，实跑，非推断）

在临时仓库复现「全树通配 restore」的行为：

| 文件状态 | 跑 `git restore --source=HEAD --staged --worktree .` 之后 |
|---|---|
| `??` 未跟踪 | **存活**（命令不动它） |
| `A ` 已暂存、但 HEAD 里没有 | **被删除**（索引 + 磁盘双双消失） |

### 结论（按诚实三分类标注）

- **事实**：那条恢复命令只删「已暂存但 HEAD 无」的文件，**不动 `??` 未跟踪文件**。
- **判断**：文件在切分支前是 `??`，所以**单靠恢复命令不该删掉它** →
  更可能是**`git checkout main` 触发的那次索引异常**把它卷走的（异常当场把 111 个跟踪文件标成删除，
  索引处于损坏状态，此时它的行为不可信）。
- **未验证**：无法确定唯一机制；也无法证明损坏的索引当时是否把该文件纳入了条目。**不编造定论。**

### 影响与处置

**影响很低**：该文件是功能开工用的提示词草稿，**功能已开发完并合并**，它的使命已完成；
且其内容以「用户在对话里发的那版提示词」形式完整留痕（本会话上下文 + PROGRESS.md 的记录）。
**处置**：未擅自重建（重建版必然与原字节不同，写成"原文件"反而有害）。
已向用户报告并提出：需要的话可按对话内容重建一版**并明确标注为重建版**，由用户决定。

### 流程加固（已写进 MEMORY.md）

下一次跑那条恢复命令之前：**先把 `git status --short` 里的 `??` 清单抄下来，并把未跟踪文件备份出仓库**。
