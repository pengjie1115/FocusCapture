# DECISIONS — 决策账本（决策点卡片）

> **条目 = 决策点的当前答案。** 更新时只判一件事：**这次变更有没有新论据？**
> 有新论据/新约束 → 旧答案压进「史」一行；没有（纯横跳）→ 直接覆盖，不留痕。
> 同一决策点 30 天内翻转 ≥2 次 = 没想清楚 → 停止记账，找用户拍板。
> git 记录「改了什么」；这里只记 git 记不了的——**当前答案是什么、为什么、否决过什么**。

## D02 分支与提交纪律
- 答案：feature 分支开发；**每完成一步立即提交**；提交信息走 UTF-8 无 BOM 文件 + `git commit -F`；暂存前必查 `git diff --cached --stat`，禁 `git add -A`
- 史：「攒到最后统一提交」已否——出问题无法回退到上一步干净状态；中文直接传参已否——PowerShell 给原生 exe 传参被 GBK 破坏

## D03 检查点纪律
- 答案：**红不许瞒**——检查点红了宁可挂着；先自验修检查点，不许放宽凑绿；交付必须附可见测试输出
- 否决：「这算需求变更」式的自行放宽；按条数猜瓶颈（耗时与条数无关，先看耗时表）

## D05 界面主题

## D06 同步里的「删除」

- 史：并集合并已否——删掉的记录会被他端复活；「未知分组」幽灵分区由此而来
