`start` / `merge` / `push` 会改变仓库或远程状态，**留给真实使用时验证**（已单独测 `start` 的参数校验分支）。

**实测踩到并修掉的 5 个坑（本轮最值钱的产出，已写进 `docs/dev-script-plan.md` 附二）**
1. 脚本**不能**改 `[Console]::OutputEncoding` —— 它是被父进程调用的，父进程按 GBK 解码，改了反而全乱
2. git 仓库内容是 **UTF-8** 字节，必须在**调用 git 那一段**临时切解码、调完立刻还原（`Get-Git`）
3. 外部程序输出**必须先捕获、恢复编码后再输出**，否则会流进函数返回值、和退出码混成数组
   （现象：检查点 31 项全过、退出码本是 0，脚本却报失败，且「退出码」字段塞满整段输出）
4. 检查点 .bat 按 UTF-8 输出且末尾有 `pause` → 临时切解码 + `'' | & $bat` 喂空行防卡死
5. **GUI 程序（FocusCapture.exe）用 `&` 调用时 PowerShell 不等它跑完、也不给退出码**
   → 改用 `Start-Process -Wait -PassThru`，并且**看产物（有没有 PNG）不看退出码**。
   这条最值钱：**能用产物证明的，就不信声明的退出码**

## 合并 + 推送（14:3x–14:5x）—— 一次性验证了 merge / push / recover

**结果**：`main` 上 5 个提交，**双远程均已推至 `876577f`**（`ls-remote` 实测两侧哈希一致）；
本地只剩 `main` 一个分支（已合并分支按规范删除），工作区干净。

**这一轮是脚本的真实压力测试，抓到 3 个真问题：**

1. **`merge` 的判据写错了** —— 原用「切换前后跟踪文件数是否一致」判索引异常，
   但切分支本来就会换一整套文件（实测 main 比本分支多 4 个：本分支删了 8 个、加了 4 个），
   文件数必然变化 → 报假警报。**改为只判「切换后工作区是否干净」**。

2. **「checkout 丢文件」在本机是稳定复现的**（不是偶发）：切到 main 丢 18 个、切回分支丢 8 个、
   merge 完成后又丢 8 个 —— **三次全中，丢的是同一批**（`docs/` 下 8 个网站素材 + `tools/` 下 10 个诊断工具），
   索引完好、能 restore。
   → 结论：**只报警等于每次都卡住**，改为**自动恢复**（`git restore --worktree`，
   只写工作区、不动索引、不删文件；比记忆里那条带 `--staged` 的全树通配安全）。

3. **`push` 在沙箱 PowerShell 里必然失败** —— 根因查清了，**不是「PowerShell 里 git 失效」**，
   而是**沙箱里系统 git 出不了网**：

   | 环境 | git | 网络操作 |
   |---|---|---|
   | bash 会话 | PortableGit 2.55.0 | **正常**（Gitee 一次成功） |
   | PowerShell 会话 | `C:\Program Files\Git\cmd\git.exe` | **一律 128 + 零输出** |
   | PowerShell 会话 | 同上，但本地操作（`status`） | 正常 |

   显式 `-c http.proxy=` 无效；改用 PortableGit 的 git 又缺 `GIT_EXEC_PATH`（补上仍 abort）。
   → **判据（已写进脚本）**：**非零退出码 + 零输出 = 沙箱限制；有输出 = 真实网络问题**。
   → 行动：**需要联网的 git 操作一律走 bash**。

**附带确认**：GitHub 的 `CONNECT tunnel failed, response 502` 确实是「时通时不通」——
连试 3 次失败后，隔几分钟再试**一次成功**，且落后的 5 个提交**一次补齐** ✓
印证记忆里「直接重试即可，别怕攒着」。
