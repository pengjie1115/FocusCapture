## AI 问答板块迭代需求对齐（晚间，Ask 模式多轮 + 定稿）

- 与虾哥逐条对齐 4 项需求：①会话记录坚果云同步 ②历史会话三个点菜单（批量/重命名/删除/导出/置顶/分组）③抽屉收起按钮 ④抽屉宽度可拖拽+跨启动记忆。
- 最终方案文档：根目录 `AI问答板块迭代-需求与方案文档.md`（v1.0 定稿，实施唯一依据）。
- 关键拍板记录：
  - 会话同步**不复用** SyncEngine（行模型对不上），新建独立轻量 ChatSyncEngine，**搭现有同步周期的车**（共享信号量/退避），不做独立循环；
  - 冲突策略 = 整文件 LWW；E2EE 复用授权码派生 DEK；归 FeatureSync 专业版；
  - **全局同步间隔**（笔记+会话共用合并窗口，默认 30s 下限 30s）替代会话独立间隔；轮询固定 30min 不开放调节；SyncEngine.MergeWindow 需改为读配置（对笔记同步的小改动，需回归）；
  - 退出 flush：主动退出失败必弹窗（用户否决了纯静默失败——公司没传上回家看不到的场景）；系统关机静默尽力传+下次启动补提醒；
  - 启动自动下拉：后台不阻塞、先拉后推、真写盘、在聊会话内存保护；
  - 会话回收站：独立轻量实现（trash 子目录，不碰笔记 RecycleBinService），删除标记清单+chat_trash/ 云端镜像+Purged 传播对齐笔记规则；
  - 导出四格式 MD/TXT/JSON/Word（**PDF 明确不做**）；分组只做一层不嵌套，groups.json 参与同步、同名合并；批量操作=删除/移动分组/导出。
- 状态：需求定稿，待用户切 Agent 模式实施。

- **数据层**：SessionFile +Title/Pinned/GroupId/UpdatedAt。关键设计：UpdatedAt=内容版本号（任何改动含元数据修补都刷新，同步 LWW 依据），SavedAt=展示用对话时间——重命名/置顶/分组不改对话时间但必须能传播，所以版本号必须分离。ChatGroupService（chat_groups.json，GUID id 与名称解耦：重命名分组不重写会话文件）。会话回收站=移入 chat_trash 目录。

## 踩坑

- **WorkBuddy 工具批量 Edit 有丢失现象**：同一条消息里多个 Edit 调用，个别报「成功」但实际未落盘（SessionFilePath、UpdatedAt、SessionFile 类定义三次踩中，全部靠编译报错兜住）。教训：**批量编辑后必须 grep 复核关键改动是否真实落盘**。
