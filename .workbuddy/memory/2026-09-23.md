## AI 问答云同步「删除复活」bug 调查（只查未改）

用户报：删除会话后过一会儿自动回到列表、可继续对话，回收站记录仍在，二次删除无效。

根因（ChatSyncEngine.cs）：
1. **主因**：删除闭环①只删本地文件+写清单，云端 `chat-{Id}.json` 永不删除（全项目无一处对 chat- 前缀调 DeleteFileAsync）。SyncSessionsAsync 对账时「本地缺该 Id → 当云端新会话 → LandSessionAsync 原样落地」，全程不查删除清单 → 每轮同步把刚删的会话搬回来。
2. SyncDeletionsAsync 只对 `DeviceId != 本机` 的记录做移 trash，本机删除后即使文件被重新落地也无人再清。
3. MarkDeleted 的 File.Move 遇回收站同名文件抛 IOException → 整个 try 中断 → 二次删除静默失败（只 Debug 输出）。
4. 复活后的会话可正常对话，Rev 自增后下轮推送云端，彻底洗白。

实锤：主目录与 trash 同名并存 8 个会话（d45d7e80/0dd72c3e/768da6f4/6a924050/245cd500/ca53d47e/a5331c7b/da1fea5a）；chat_sync_state.json Deletions 有对应记录；KnownStamps 中 d45d7e80 的云端 LastModified（09:39:16）晚于其删除时间（09:35:58）= 删除后云端文件又被改写上传。

修复方向（待用户拍板）：对账时以删除清单为权威（清单内 Id 不落地，且删除时顺带删云端文件）；MarkDeleted 对回收站同名冲突幂等。今天 app log 无同步行（ChatSyncEngine 只 Debug.WriteLine），日志层证据不可得，靠代码+state+目录实物定位。

## 20:10 评估「拆板块 + 组队并行开发」——结论：本项目不适用（用户提问）

用户问能否把设计稿拆多块、主 Agent 出协作契约、派子 Agent 并行开发后合并，以及 WorkBuddy 架构支不支持。

**架构层面（事实）**：支持。多 agent 团队、命名队友（SendMessage 私信/广播）、共享任务列表、每个子 Agent 独立上下文与独立权限模式、后台运行 + 完成通知、一条消息并发派多个、计划审批与关闭协议、子 Agent 类型有 general-purpose/Explore/Plan/code-reviewer。子 Agent 产出只回主 Agent（不直接给用户）。

**判定：本次改造不该拆。四条理由**：
1. **串行依赖链而非并联**：数据层 → 解析层 → {界面, 联网, 裁剪} → 交付。只有尾部三块可并行，关键路径长度没变
2. **共享文件冲突**：`Models/AppSettings.cs`（数据层改/裁剪层读）、`Windows/SettingsWindow.xaml.cs`（界面重构 + 联网层挂事件）、`OpenAICompatibleProvider.cs`（max_tokens + 裁剪接入）、`REGRESSION.md`（多方追加）→ 需 worktree 隔离 + 合并，合并成本 > 并行收益
3. **无 CI/CD + 慢层沙箱隔离有脆弱史**：今天上午刚发生慢层测试写穿真实 settings.json 的事故（根因＝定时器 + 隔离还原时序）。两个 agent 并发跑慢层会复现同类事故
4. **环境坑要重踩**：MEMORY.md 那 10 类坑（PS 执行策略 / 编译补 4 个环境变量 / 写文件假成功 / git 索引异常）是"持续上下文"攒的经验，子 Agent 不共享我的上下文，prompt 里写不全

**量化（判断非事实）**：可并行的联网层 + 裁剪层约占改造 30%，且都依赖前 70% → 总时长仅省约 15%，却要付 worktree 搭建 + 合并 + 双份编译与踩坑成本，净收益≈0。

**该用并行的场景（本项目内真实存在）**：①并行调研（如一次查 4~5 家供应商 `GET /models` 的真实返回格式）②独立评审（数据层+迁移做完后派 code-reviewer 审「保命回退」）。**结论：团队用于调研与评审，不用于并行写共享文件。**

**依据**：`dispatching-parallel-agents` skill 明写 Don't use when「Shared state: Agents would interfere (editing same files)」；`agent-team-orchestration` 明写「Single-agent setups — team orchestration adds overhead that solo agents don't need」。
