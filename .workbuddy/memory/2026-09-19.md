## 悬浮球角标修复 + 自定义图标两处同源（分支 `fix/badge-and-icon-sync`，commit `c7cfc18`）

### 一、悬浮球角标（`Windows/FloatBall.xaml`，纯样式）

- **圆被切一块**：角标用的是**负边距** `Margin="0,-2,-2,0"`，被顶出 48×48 窗口的右边、上边各 2px；
  窗口矩形之外一律不渲染（WPF 在这层没有裁切余地）→ 圆缺一块。
  现收到窗口内（右边留 1px），角标中心仍落在球圆周上，视觉位置没变。
- **数字偏上**：数字靠 `Border` 的 `Padding` 撑位，而 `TextBlock` 被拉伸填满后文字按行顶对齐。
  改为 `TextBlock` 自己 `HorizontalAlignment/VerticalAlignment=Center`。
  像素实测垂直偏差 **0.06 逻辑像素**（改前约 0.7）。
- 未动 `FloatBall.xaml.cs` 一行，拖动 / 吸附 / 角标点击逻辑零影响。

### 二、自定义图标两处同源（新增 `Services/AppIconService.cs`）

- **根因（事实，非回归）**：全项目 20 个窗口**一处都没设过窗口图标**，全部走 exe 编译期 `app.ico`；
  自定义图标此前只在托盘那一处生效 → 托盘变了、任务栏不变。
- **机制**：ClassHandler 钩 `Window.Loaded`，一处注册覆盖全部窗口（含以后新增的，逐个改必漏）。
  换图 → `Reload` + 重建托盘 + `RefreshOpenWindows`，三步跑完才叫同源，全程不必重启。
- **顺带补的缺口**：清自定义图标时要能「清回默认」—— 判据是窗口自身的 `Icon` 属性（非 null 说明本服务设过），
  否则点「恢复默认图标」又会出现"托盘已回退、任务栏还挂旧图"的二次不同步。
  从未被设过的窗口一律不碰，保证默认外观与改造前完全一致。
- **顺手修掉 use-after-free**：旧写法把 HICON 交给 `NotifyIcon` 之后立刻 `DestroyIcon`，
  托盘长期握着已失效的句柄（可能变空白/画错却不报错）。改为 `Clone` 出自有句柄的 Icon，调用方负责 Dispose。
- 沉浸记录最小化到托盘的那个图标（原先是硬编码绿方块）也改为同源。

## 第三轮：角标外移 + 投影去硬边（同分支，commit `ad5ddce`）

用户看完上一版效果后的追加反馈：「角标和球压得太多，往外移一点」+「投影看着怪怪的，特别是浅背景」。
两块都卡在同一个结构约束上，所以合成一次改动。

### 一、角标外移 —— 真正的卡点是窗口，不是角标

- 角标圆心本来**正好落在球边上**（距球心 20px = 球半径）→ 一半压在球上，重叠 **9px**。
- 想少压只能往外推；往外推就出窗口（窗口外一律不渲染，上一轮刚踩过）→ **必须先给窗口腾地方**。
- 窗口 48→56（**球恒 40×40 未变，变的是四周留白 4px→8px**）；角标 Margin 右/上各 1.5px
  → 圆心距球心 **24.75px**，移出球边 4.75px，重叠 **9px → 4.25px**。
- **顺带解掉一个隐藏问题**：悬停时球放大 1.1 倍（半径 20→22），旧位置圆心只有 20.5px
  → 放大瞬间角标圆心会**陷进球体**、像被球咬掉一块。24.75 > 22，现在放大时也在球外。

### 二、投影被窗口削平（实测出来的，不是猜）

- 参数：模糊 8 / 偏移右下 2 / 自身不透明度 0.5，另叠 window 的 0.85。
- **6 倍快照逐像素量 alpha**：四个方向到窗口边界的余地都是 4px，但——
  下 75/255(29%) → 边界仍剩 **18/255(7%)** 被硬切；右 70 → **16/255(6%)** 被切；
  上 28 → 2(0.8%)、左 25 → 1(0.4%)，自然淡出。
  即**空间一样多，但投影强的方向淡不完** → 下方/右侧一道生硬平边。
- 深色桌面同色看不见，浅色桌面扎眼 —— 解释了用户「特别是浅背景」。
- 调参：模糊 **8→10**、自身不透明度 **0.5→0.3**，偏移仍朝右下 2px（保留方向感）。
  改完四边边界实测只剩 **0~1/255**。
- **经验式（实测反推）**：投影淡完所需余地 ≈ 模糊半径/2 + 偏移。两个数据点都对上
  （旧 4 vs 需 6 → 被切；新 8 vs 需 7 → 干净），已固化进慢层检查点。

### 三、⚠ 更正上一轮的一个错误结论

上轮告诉用户「扩窗口会把点击热区从 4px 扩到 8px、挡住下层点击」——**错的**。
`Diagnostics/UiSnapshot.cs` 自己的注释就写着「球窗口的透明区穿透」，透明像素不吃点击，
扩窗口多出来的那圈是全透明的，代价≈0。用户据此才拍板扩窗口。已在对话中当面更正。
