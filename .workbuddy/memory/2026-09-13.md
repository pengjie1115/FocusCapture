## 灵感速览标题栏自定义：设置面板三处疑点排查（未改代码）

分支 `feature/quickview-customizable-toolbar`（未合并 main，最新提交 `ea27eac`）。用户报三个问题，逐一定位：

### 1. 列表项文字看不清 —— 真 bug（对比度）
- **现象**：工具栏"左侧区域/右侧区域"两个 ListBox，只有被点选中的那一项文字清楚，其余全部看不清。
- **像素实测（截图像素采样，非目测）**：列表背景 `#252526`（亮度 37）；未选中项文字右侧实测 `#373737`（55）、左侧约 `#6B6B6B`（107）；选中项文字 `#DADADA`（218）。同窗口导航栏/标签文字实测均为 `#E0E0E0`（224）。
- **根因**：这两个 ListBox 没设 `ItemContainerStyle`，落到系统默认 ListBoxItem 样式（未选中态 Foreground = 系统控件文字色≈黑，不继承窗口 Foreground）。对比：导航列表用 `NavListItem` 自定义样式（无 Foreground setter）→ 继承窗口 `#E0E0E0` → 正常。**"自定义模板不带 Foreground setter"反而是对的做法**。
- **修复方向**：补 `ItemContainerStyle`，显式设 Foreground（含选中态）。

### 2. "添加"下拉框点开空白 —— 非 bug，是"确实没得选"
- 该下拉 = "尚未启用的功能"选择器。功能目录共 **8 个**（`QuickViewToolbarCatalog.All`），默认左 3 + 右 5 = 8 全启用；`FillToolbarCombo` 跳过已启用项 → 无可选项。

### 3. "添加"按钮点了没反应 —— 同一根因
- `ToolbarAdd_Click` 首行 `if (combo.SelectedItem is not ComboBoxItem { Tag: string id }) return;`；下拉空 → SelectedItem 为 null → 直接返回。按钮也没做空态置灰。

### 定性结论
- 问题 2/3 不是 bug，是**设计缺陷**：可用功能池只有 8 个且默认全启用，"自定义"实际只能"先移除才能添加"，而 UI 零引导。
- 待用户拍板修复方案：A 空态提示+按钮置灰（最小）／B 允许两侧重复／C 扩充功能目录。

## 实现（同分支，已提交 `5f19543`）

用户拍板：A 类 5 个功能全加（默认布局仍保持 8 个）；图标改系统矢量字体 + 统一外观；做界面快照工具并**长期保留**；UI 修复范围扩到其他窗口，但**严禁连带损坏、有取舍先报**。

### 新增：界面快照工具（`Diagnostics/`，长期保留，用户要求）

- `FocusCapture.exe --snapshot [--out <dir>]` → 把窗口**真实渲染**成 PNG（用程序自身样式资源，不是另起炉灶）
- 覆盖 13 个场景（含「标题栏全功能预览」「图标字符自检」「全启用空态」）
- **关键设计**：强制 `FocusCapturePaths.RootOverride` 指向临时沙箱，绝不读写真实 `%AppData%`；沙箱用完即删
- **零侵入**：`App.xaml.cs` 只加一处 `if (UiSnapshot.IsRequested(e.Args))`，正常启动不进入该分支
- **价值**：它是唯一能发现「控件被挤出可视区 / 图标字形缺失（豆腐块）/ 文字对比度过低」的手段 —— 这三类静态代码完全看不出来
- 文档 `Diagnostics/README.md`；REGRESSION.md 盲区段已登记为「半自动通道」（降发现成本，不替代判断）

### 图标矢量化的三个根因（重要，都值得记）

1. **动态状态文案覆盖图标**：同步按钮 Content 被 `ApplySyncButton` 改成 `"↑"/"↓"`（及 `"上传中…"`），而 FontFamily 已是 `Segoe MDL2 Assets` → 该字体无此字形 → **空框**
2. **代码回写文本字符**：`BtnMaximize.Content = "❐"/"□"` 同理
3. **全局样式 Padding 挤压**：`App.xaml` 全局 Button 带 `Padding="8,4"`，28px 图标钮内容区只剩 12px → 图标挤偏/裁切

> **教训**：换图标字体时，必须把**所有运行时会改写 Content 的地方**一并排查（`grep '\.Content ='`），否则静态代码看不出任何问题。

> **MDL2 图标代码不能靠记忆猜** —— 我先用 PIL 把 `segmdl2.ttf` 字形渲染成对照表才选准。已固化为工具内「图标字符自检」窗口（`GlyphProbe`）。
> 实测可用：E721 查找 / E72C 刷新 / E74A 上传 / E74B 下载 / E74E 保存 / E74D 删除 / E713 设置 / E8B5 导入 / E8FD 列表 / E787 日历 / E8BB 关闭 / E921 最小化 / E922 最大化 / E923 还原。
> **注意**：E74E 是"软盘=保存"；曾误以为它是喇叭（网格表数错行所致）—— 所以对照表要**一代码一行**才可靠。
